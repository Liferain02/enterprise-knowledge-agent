# 分布式 NUMA 课题组会模板

## 适用场景

本模板用于分布式 NUMA、远程内存、RDMA 资源池化、数据中心 OS 等相关课题的周组会或阶段汇报。

## 一、问题背景

请用 2 到 3 页讲清楚以下问题：

- 你要解决的核心系统问题是什么
- 这个问题为什么重要
- 当前已有系统为什么还不够
- 你的问题更接近性能问题、抽象问题，还是资源管理问题

## 二、相关工作

至少回答以下四个问题：

1. 相关系统做了什么
2. 它们依赖什么硬件或系统假设
3. 它们的瓶颈在哪里
4. 你的工作与它们相比新增了什么

建议不要只列论文名称，而要按“抽象层次 / 资源管理方式 / 性能目标”组织。

## 三、系统设计

建议按照以下结构讲：

### 1. 系统接口

- 应用如何使用该系统
- 应用是否显式感知远端资源
- 是否暴露远端 NUMA 节点或逻辑资源池

### 2. 数据路径

- 请求如何从本地发出
- 何时走 RDMA
- 何时访问远端内存
- 本地路径和远端路径如何切换

### 3. 控制路径

- 资源如何分配
- 谁负责调度
- 如何处理资源竞争和回收

## 四、实验设计

必须包含：

- baseline 系统
- 测试平台
- 关键硬件信息
- 工作负载说明
- 评测指标

建议至少有以下几类实验：

1. 本地访问与远端访问代价对比
2. 不同 NUMA / 分布式 NUMA 布局策略对比
3. 不同负载强度下的延迟与吞吐对比
4. 不同节点规模下的扩展性测试

## 五、当前进展

按下面格式汇报最清楚：

- 已完成：
- 正在进行：
- 主要阻塞：
- 下周计划：

## 六、答辩式提醒

如果你的汇报涉及分布式 NUMA，一定要明确回答下面几个问题：

- 为什么这是“NUMA 问题”而不是一般远程内存问题
- 你的抽象与传统单机 NUMA 有什么继承关系
- 应用是否需要修改，修改成本多大
- 当远端访问比例升高时，系统还能否保持稳定

## 七、推荐附录

建议附录中保留：

- 关键图表
- 参数表
- 节点拓扑图
- 实验脚本入口
- commit id
