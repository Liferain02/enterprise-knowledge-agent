# 实验室成员与分工说明

## 一、文档目的

本文档用于说明实验室当前的成员构成、常见角色职责和协作分工，方便新成员快速了解“遇到什么问题找谁”。

## 二、成员角色划分

实验室成员通常分为以下几类：

### 1. 导师 / PI

- 负责整体研究方向规划
- 决定重点课题与阶段目标
- 指导论文选题、系统设计和实验路线
- 审核重要项目节点与论文投稿材料

### 2. 教师 / 联合指导教师

- 协助推进具体方向研究
- 参与组会讨论与阶段性评估
- 指导系统实现、实验方法和论文写作

### 3. 博士生 / 高年级骨干

- 负责重点课题推进
- 维护部分核心代码仓、实验平台和共享脚本
- 指导低年级同学阅读论文和搭建实验环境
- 协助组织方向内部讨论

### 4. 硕士生

- 围绕具体课题开展阅读、系统实现与实验评测
- 按要求提交周报和组会汇报
- 维护自己负责部分的实验记录与项目文档

### 5. 本科助研 / 访问学生

- 在导师或高年级同学指导下完成子任务
- 优先负责环境熟悉、模块测试、论文调研、文档整理等工作

### 6. 实验室管理员 / 秘书

- 负责公共设备、资产、账号、会议室、报销材料等行政协调
- 管理公共资料入口、表单模板和通知归档

## 三、常见问题的责任分工

### 环境与平台问题

- 代码仓访问问题：先联系项目负责人
- 服务器账号开通：联系实验室管理员
- GPU / RDMA 节点使用冲突：联系平台维护负责人
- 公共环境损坏：第一时间在组内说明，并联系平台支持同学

### 项目与课题问题

- 研究方向理解不清：先查方向资料，再联系直接指导老师
- 系统设计细节不明确：联系项目负责人或高年级骨干
- 实验结果异常：先检查记录，再与课题组内同学讨论

### 行政与流程问题

- 请假 / 外出：按实验室请假流程报备
- 报销 / 采购：查看报销流程说明和模板目录
- 会议注册 / 差旅：联系实验室管理员确认流程

## 四、对成员的基本要求

- 所有成员都应维护基本的实验记录
- 所有项目都应保留 README 和必要使用说明
- 重要问题优先在组内公共渠道同步，避免口头单线沟通造成信息丢失
- 任何对公共环境的改动都必须记录

## 五、新成员建议

新加入成员建议按以下顺序熟悉实验室：

1. 看实验室研究方向与课题地图
2. 看环境配置说明和集群使用规范
3. 看组会制度、周报制度和考勤要求
4. 找到自己所属项目的资料入口
5. 了解对应项目负责人和平台支持同学
