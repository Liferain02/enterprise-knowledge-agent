# 启动与远程访问指南

本文说明如何在 `cpui01` 启动、停止和访问项目，以及 SSH `-L`、`-R` 的区别。项目优先使用：

- 前端：`3000`
- 后端：`8010`
- `5173`、`5174`、`8000` 留给其他项目

如果服务器的 `3000` 已被其他服务占用且 `frontend/dist` 已构建，启动脚本不会终止未知进程，而是自动切换到 `8010` 前后端一体模式；此时产品页面与接口文档都通过 `8010` 访问。以脚本最后打印的地址为准。

## 一键启动与停止

登录 `cpui01`，进入项目目录：

```bash
cd /share/home/lifr/workspace/code/enterprise-knowledge-agent
./scripts/start.sh
```

启动脚本会完成以下工作：

1. 检查 `config/.env`、Conda `agent-demo` 环境和前端依赖。
2. 检查 `3000/8010` 是否被其他进程占用；`3000` 冲突时选择安全的一体模式。
3. 启动后端并等待 `/health/ready` 返回成功。
4. `3000` 空闲时启动 Vite；否则由 `8010` 托管已构建前端。
5. 将 PID 和日志写入 Git 忽略的 `.run/` 目录。
6. 重复执行时识别已有进程，不重复启动。

停止项目：

```bash
cd /share/home/lifr/workspace/code/enterprise-knowledge-agent
./scripts/stop.sh
```

停止脚本只处理 `.run/` 中记录且命令行属于当前项目的 PID，不会按端口模糊杀进程。

## 为什么 `ssh -R` 无法打开项目

两种转发方向不同：

| 参数 | 方向 | 本项目用途 |
|---|---|---|
| `-L 本地端口:目标地址:目标端口` | 本地电脑 → SSH 服务器 | 从你的电脑访问服务器上的前端和后端 |
| `-R 远端端口:目标地址:目标端口` | SSH 服务器 → 本地电脑 | 让服务器访问你电脑上的代理等服务 |

因此：

```bash
ssh -R 7897:127.0.0.1:7897 cpui01
```

只会让 `cpui01:7897` 转发到你电脑的 `127.0.0.1:7897`。这适合把本机代理提供给服务器，但没有建立项目 `3000/8010` 的本地访问通道。

正确的项目访问链路是：

```text
本地浏览器
  → 本地 127.0.0.1:3000
  → SSH -L 隧道
  → cpui01 的 127.0.0.1:3000
  → Vite 前端
  → /api 请求由 Vite 代理到 127.0.0.1:8010
```

## 推荐的 SSH 命令

先在 `cpui01` 上执行 `./scripts/start.sh`。然后在你自己的电脑上另开一个终端执行：

```bash
ssh -N -T \
  -o ExitOnForwardFailure=yes \
  -L 3000:127.0.0.1:3000 \
  -L 8010:127.0.0.1:8010 \
  cpui01
```

ssh -R 7897:127.0.0.1:7897 -L 13000:127.0.0.1:3000 -L 18010:127.0.0.1:8010  cpui01

注意：这条命令必须在你的电脑上运行，不是在已经登录的 `cpui01` 终端里运行。命令运行期间终端不显示 shell 提示符是正常现象，必须保持该 SSH 进程运行。

建立隧道后，在你自己的电脑上打开：

- 产品页面：<http://127.0.0.1:3000>
- 后端文档：<http://127.0.0.1:8010/docs>
- 健康检查：<http://127.0.0.1:8010/health>

正常使用产品页面只需要转发 `3000`，因为前端会代理 `/api`。转发 `8010` 主要用于查看接口文档和直接调试后端。

如果 `start.sh` 显示“前后端一体模式”，只需转发 `8010`，然后直接打开 `http://127.0.0.1:8010`；不要访问服务器上已被其他项目占用的 `3000`。

## 同时把本机代理提供给服务器

如果你还需要让 `cpui01` 通过你电脑的 `7897` 代理访问网络，可以同时使用 `-R` 和 `-L`：

```bash
ssh -R 7897:127.0.0.1:7897 \
  -L 3000:127.0.0.1:3000 \
  -L 8020:127.0.0.1:8010 \
  cpui01
```

这里三个参数各自独立：

- `-R 7897...`：服务器使用你电脑的代理。
- `-L 3000...`：你电脑访问服务器前端。
- `-L 8010...`：你电脑访问服务器后端。

## 本地端口已经被占用

SSH 命令如果提示 `Address already in use`，说明你电脑上的 `3000` 或 `8010` 已被占用。只修改冒号左侧的本地端口：

```bash
ssh -N -T \
  -o ExitOnForwardFailure=yes \
  -L 13000:127.0.0.1:3000 \
  -L 18010:127.0.0.1:8010 \
  cpui01
```

此时访问：

- 产品页面：<http://127.0.0.1:13000>
- 后端文档：<http://127.0.0.1:18010/docs>

右侧 `3000/8010` 是服务器端口，不能改；左侧 `13000/18010` 是你电脑上的端口，可以自行选择未占用端口。

## 分步排查

### 第一步：确认服务器服务正常

在 `cpui01` 执行：

```bash
cd /share/home/lifr/workspace/code/enterprise-knowledge-agent
./scripts/start.sh

curl --noproxy '*' -I http://127.0.0.1:3000/
curl --noproxy '*' http://127.0.0.1:8010/health
```

预期结果：前端返回 `HTTP/1.1 200 OK`，后端 JSON 中的顶层 `status` 为 `healthy`。

查看启动日志：

```bash
tail -n 100 .run/前端.log
tail -n 100 .run/后端.log
```

持续观察日志：

```bash
tail -f .run/前端.log .run/后端.log
```

### 第二步：确认 SSH 本地转发成功

在你自己的电脑上使用详细日志启动隧道：

```bash
ssh -v -N -T \
  -o ExitOnForwardFailure=yes \
  -L 3000:127.0.0.1:3000 \
  -L 8010:127.0.0.1:8010 \
  cpui01
```

成功时会出现类似信息：

```text
Local forwarding listening on 127.0.0.1 port 3000
Local forwarding listening on 127.0.0.1 port 8010
```

然后在电脑上的另一个终端执行：

```bash
curl -I http://127.0.0.1:3000/
curl http://127.0.0.1:8010/health
```

### 第三步：按错误类型处理

- `Connection refused`：服务器服务未启动，或 SSH 命令右侧端口写错。
- `Address already in use`：本地端口冲突，改用 `13000/18010`。
- `administratively prohibited`：SSH 服务端禁止端口转发，需要管理员开启 `AllowTcpForwarding`。
- SSH 隧道正常但浏览器打不开：确认浏览器访问的是本机 `127.0.0.1`，并临时关闭浏览器代理对本地地址的接管。
- 服务器本机访问正常、SSH 报 `connect failed`：确认隧道连接到的确实是运行项目的 `cpui01`；若使用跳板机，应继续通过现有 SSH 配置或 `-J` 连接最终主机。
