# 03 自动测试、访问控制矩阵与浏览器验证

项目质量保障分为确定性单元/契约测试、真实依赖评测、API 运行验证和浏览器产品测试。它们覆盖不同风险，不能互相替代。

## 03.1 测试金字塔

```text
大量：纯函数、schema、路由、ACL、状态契约
中量：Service/DAO/临时 SQLite/Mock LLM
少量：真实 Chroma + 真实模型评测
少量：启动前后端 + 浏览器端到端
```

真实模型测试昂贵且有波动，不适合作为每次提交的全部单元测试；纯 mock 测试又不能证明 API/模型实际可用。

## 03.2 当前冻结基线

V2 冻结时后端为 272 passed，前端 TypeScript/Vite build 通过。这个数字是 commit 和环境快照，不是永久保证；新增测试或依赖变化后必须更新。

## 03.3 图结构契约

测试应验证：

- Planner 是唯一入口路由。
- production graph 不注册 Supervisor/parallel executor。
- Retrieval 后固定进入 Generation。
- Deep 只有固定三角色与一次 revision。
- 所有分支进入 Finalizer。
- Deep 必须显式 mode。

这能防止某次重构把历史代码悄悄接回主链。

## 03.4 AgentState 契约

构造最小 state 验证每个节点只读所需字段，并返回合法 key。特别检查：

- 空消息有稳定兜底。
- Finalizer 不重复 AIMessage。
- tool/internal messages 不进入摘要与 Mem0。
- retrieval decision 和 docs 能被 Generation 消费。
- Deep schema 可以 model_validate。

## 03.5 Planner 测试

输入问候、计算、普通知识、对比、多文档和显式 Deep，检查 route 与 expansion：

```text
问候 → general
计算/时间 → operation
普通知识 → retrieval, no expansion
复杂列举 → retrieval, expansion
deep mode → research
```

规则和 Query Expansion pattern 要有同步回归测试。

## 03.6 摘要测试

- 小于阈值返回空更新。
- 只计 human/ai。
- 保留最近 N 条。
- 生成 RemoveMessage IDs。
- 旧 summary 会进入滚动 prompt。
- tool messages 不被格式化进摘要。

需要 mock LLM 避免每个单测调用外部模型。

## 03.7 检索测试

纯函数覆盖分词、权重、RRF 和无意义查询；集成测试用冻结 Chroma 运行真实问题，检查文档级命中、去重和 no-answer。

Reranker 测试同时覆盖正常 API response、非 200、ImportError 和 exception 降级，确保失败保持候选顺序。

## 03.8 ACL 单元矩阵

对每个角色与 metadata 组合直接调用 `check_doc_access()`，覆盖：

- confidentiality 等级边界；
- public/project/restricted；
- department 空/匹配/不匹配；
- role restrict；
- inactive 用户；
- 字段为 string/list/empty 的兼容。

## 03.9 Deep ACL 全阶段测试

`tests/test_deep_research_acl_matrix.py` 不只检查最终答案，还验证：

1. Researcher query 接收 UserContext。
2. EvidencePackage 无 forbidden evidence。
3. Analyst Claim source IDs 均合法。
4. Reviewer/Revision 不重新引入受限内容。
5. final sources/answer 无污染标识。

这比只对最终字符串搜关键词更能定位泄漏阶段。

## 03.10 对抗污染文档

构造与 query 高度匹配但 visibility/confidentiality 禁止的文档。如果检索只看相关度，它会排名第一；正确实现必须在候选或 Python check 阶段删除。

污染测试验证“权限优先于相关性”，是 ACL 最有价值的测试之一。

## 03.11 入库队列测试

- enqueue 字段完整。
- dequeue 状态变 running。
- complete 保存 result。
- fail 在阈值内 retrying、到阈值 failed。
- stale running 恢复。
- SHA-256 重复不再 embedding。
- 新向量写入失败时旧 IDs 仍在。

测试使用临时 SQLite 和 mock vector manager，避免修改真实数据。

## 03.12 Session 隔离测试

Alice/Bob 使用相同 external session ID：

- 内部 ID 不同；
- 历史互不可见；
- 删除 Alice 不影响 Bob；
- graph thread ID 不同；
- session list 只返回当前用户。

## 03.13 认证测试

覆盖 Argon2、旧 hash 升级、JWT 过期、用户删除、角色更新、config admin 和同名冲突。测试不能把真实密码或 key 写入仓库。

## 03.14 SSE 契约测试

模拟多个 nested LLM events，检查只有 `user_visible_answer` tag 被发成 llm_token；Planner/Reviewer JSON 不泄漏。

还应覆盖：

- no-token 分支结束后补发 final answer；
- sources/used agent/version/done 顺序；
- exception 发送 error 并结束；
- JSON 中中文、换行正确编码。

## 03.15 前端构建测试

`vue-tsc` 发现接口类型和模板引用错误，Vite build 验证模块打包。它不能发现运行时 SSE 分帧、按钮语义或实际 API 错误。

## 03.16 真实浏览器测试

启动前后端后，用真实鼠标/键盘覆盖：

1. 登录与页面恢复。
2. 创建/切换/重命名/删除会话。
3. Normal 问答与来源卡片。
4. Deep 单次选择和复位。
5. 上传文件、观察 job 状态、目录刷新。
6. 搜索和 metadata 筛选。
7. helpful/incorrect/missing feedback。
8. 管理员处理 issue。
9. 科研项目、实验、组会待办。
10. 不同 viewport 与错误网络。

## 03.17 为什么要真实输入点击

直接调用 API 看不到：

- disabled 状态是否正确；
- loading 是否清理；
- token 是否重复/丢失；
- 来源是否在流结束后出现；
- 输入框和滚动是否可用；
- 小屏布局是否遮挡。

浏览器测试验证产品链，而不是只验证后端函数。

## 03.18 真实模型评测隔离

运行前固定代理、模型、知识库和配置。真实 API 可能限流/波动，所以原始结果必须保存错误类型，不应自动无限重跑直到得到好结果。

限流错误是可用性数据，不能悄悄从汇总中删除。

## 03.19 测试数据安全

- 使用合成账号和文档。
- 不把实际 API key 写 fixture。
- 临时数据库用 tmp path。
- 浏览器截图不包含敏感 restricted 内容。
- 日志只记录 source ID/元数据摘要。

## 03.20 发布前最小门禁

```text
git diff/check clean enough for intended scope
pytest passes
frontend typecheck/build passes
ACL matrix passes
Normal smoke succeeds
Deep switch/offline behavior succeeds
ingestion smoke succeeds
docs/links/config match current behavior
```

文档改动无需重复昂贵真实模型评测，但业务代码或配置变化必须按影响范围重跑。

## 03.21 尚缺的测试

- 前端 SSE 跨 chunk buffer 自动测试。
- 浏览器取消到后端 task cancellation。
- Markdown XSS 专项。
- 多进程 ingestion dequeue 竞争。
- 长时间运行的内存/连接泄漏。
- 更丰富部门树和权限变更并发。

主动指出测试空白比仅报告“272 passed”更可信。
