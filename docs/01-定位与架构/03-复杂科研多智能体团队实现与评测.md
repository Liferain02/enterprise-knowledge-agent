# 选择性深度研究多智能体实现与评测

本文描述选择性深度研究模式的当前实现与历史评测。它不是默认回答链，也不是自动多智能体路由：调用者必须在聊天请求中显式设置 `research_mode=deep`。未设置或设置为 `normal` 时，系统保持查询扩展 → 检索 → 回答生成，不增加额外的团队调用。

> 当前结论请以《../03-评测与验证/02-秋招版评测收口说明.md》为准。本文的开发集/盲测数据是冻结历史记录，只用于解释评测方法和深度研究模式的边界；不应当作新的待办或全局产品收益结论。

文档基线：2026-08-13（历史快照）。模型、向量表示、重排模型、知识库、ACL、切块与框架均沿用当时配置；当前结论以 2026-09-07 的评测收口说明和秋招文档为准。

## 1. 当前产品决策

系统保留两种清晰模式：

| 模式 | 入口 | 适用问题 | 工作流 | 默认 |
|---|---|---|---|---|
| `normal` | 请求不传或显式传 `normal` | 普通知识问答、制度、单事实、一般对比 | 路由规划器 → ACL RAG → 回答生成 | 是 |
| `deep` | 请求显式传 `deep` | 多证据综合、时间/冲突、证据化建议、前提核验、研究简报 | 资料研究员 → 分析员 → 审核员 → 最多一次修订 → 既有回答生成 | 否 |

历史盲测 V1 的答案级盲评曾只在 `temporal_conflict` 类观察到净收益：深度研究模式平均 6.00/6，普通模式为 4.67/6，3 条中深度研究模式胜 2 条。这是历史信号，不是 V2 的新盲测结论。V2 自动指标显示文档召回和引用覆盖提高，但前提判断安全指标从普通模式的 0.667 降到深度研究模式的 0.167，已触发预声明红线。因此当前只能保持原有窄边界：

- 允许用户显式选择深度研究模式；
- 不自动把任何问题升级为深度研究模式；
- 不替换普通模式；
- 不增加前端复杂自动路由；
- 不宣称深度研究模式对所有科研问题更好；
- 在获得新的独立真人或用户证据前，不扩大产品声明或自动适用范围；模型模拟评分只用于失败分析。

## 2. 明确不做什么

本实现没有引入 Supervisor、第四个智能体、动态工作进程、智能体自由协商、智能体间长期记忆、Blackboard、消息队列、Redis、Kafka、GraphRAG、新向量库、新模型或新智能体框架。审核员没有循环回边，资料研究员不绕过 ACL，终态整理器不是新智能体。

## 3. 请求入口

非流式与流式请求模型都有同一个字段：

```json
{
  "message": "综合近期 RDMA 资料，分析冲突并给出下一步研究建议",
  "session_id": "research-001",
  "research_mode": "deep"
}
```

Pydantic 只接受 `normal | deep`，默认 `normal`。控制器原样传入 `ChatService.achat()` 或 `ChatService.achat_stream()`。`DEEP_RESEARCH_ENABLED` 是部署门禁；盲测达标后模板和默认配置为 true，运维仍可设为 false 立即下线深度研究模式，不影响普通模式。

项目没有自动判断后悄悄进入深度研究模式。`route_from_planner()` 只检查显式状态：

```python
if state.get("research_mode", "normal") == "deep":
    return "research_agent"
```

其余路由规划器逻辑保持不变。

                                          → research_revision  │      │

## 5. 状态协议

深度研究模式只在现有 `AgentState` 增加业务字段，不建数据库：

| 字段 | 生产者 | 消费者 | 内容 |
|---|---|---|---|
| `research_mode` | API/调用入口 | Router | `normal` 或 `deep` |
| `research_question` | 资料研究员 | 后续节点 | 原始问题 |
| `evidence_package` | 资料研究员 | 分析员/审核员/修订/回答生成 | ACL 校验后的证据 |
| `analysis_report` | 分析员/修订 | 审核员/回答生成 | 结构化声明映射 |
| `review_report` | 审核员 | 修订/回答生成 | 声明、前提、冲突复核 |
| `research_revision_count` | 修订 | Router/诊断 | 只允许 0 或 1 |
| `research_team_metrics` | 全阶段 | Eval/诊断 | 调用、词元、耗时 |
| `research_trace` | 全阶段 | Eval/诊断 | 端到端阶段轨迹 |

## 6. 资料研究员

入口：`research_agent_node()`。

### 6.1 有限拆分

复用现有 `QueryDecomposer`，最多 4 个子问题。结构化调用失败时使用 `_fallback_subquestions()`，不会创建角色或无限扩展。

```text
MAX_SUBQUESTIONS = 4
MAX_TARGETED_QUERIES = 2
MAX_EVIDENCES = 12
MAX_EVIDENCE_CHARS = 800
```

### 6.2 只使用既有检索

每个子问题调用与普通模式相同的 `_retrieve_documents()`，并固定 `needs_expansion=False`，因为问题已经在资料研究员中拆分。默认链是 ACL 混合检索 → Qwen 重排；只有显式设置 `CRAG_ENABLED=true` 的实验才增加 Grading/Rewrite。

### 6.3 ACL

Pipeline 的 ACL 过滤后，资料研究员再逐文档调用 `check_doc_access()`。匿名或缺失用户上下文时使用 public 权限，而非全库权限。被拒绝的文档不会进入证据包、声明、生成上下文、来源卡片或 trace。

### 6.4 证据包

```text
EvidencePackage
  original_question
  subquestions[0..4]
  evidences[0..12]
    source_id             S1..Sn
    subquestion
    title
    source                仅安全文件名
    excerpt               最多 800 字符
    score
    metadata              白名单字段
    time_info
    conflict_warnings
  missing_evidence
  conflicts
  acl_checked
```

证据按 `source + 正文前缀` 去重并按分数排序。`_documents_from_package()` 用同一顺序重建前端来源，保证 S1..Sn 与 `[文档1..n]` 一致。

## 7. 分析员

入口：`analyst_agent_node()`。分析员不能检索、不能创建智能体，只读证据包。

```text
Claim
  claim_id
  text
  claim_type: fact | comparison | inference | recommendation
  source_ids
  confidence

AnalysisReport
  claims                 最多 12
  comparison
  uncovered_source_ids
  limitations            最多 4（规范化后）
  draft_answer            正常要求留空
```

提示词要求 6～10 条紧凑声明；每条都必须绑定证据包中真实存在的 S 编号。`uncovered_source_ids` 用于诊断“检索到了但没有进入声明”的证据流失。

Qwen 的 wire format 偶尔使用 `claim_text`、`claim_content`、`content`、`category` 等字段。Pydantic alias 只做字段兼容；缺失类型默认 fact 后再按“建议/推断”等通用语义规范化，不会补造证据。

## 8. 审核员

入口：`reviewer_agent_node()`。只允许：

- `PASS`；
- `REVISE`；
- `NEED_MORE_EVIDENCE`。

ReviewReport 包含逐声明结果、`premise_assessment`、直接前提证据编号、冲突/ACL 状态和最多 2 个补检索查询。

前提协议使用四态：

- `supported`：资料直接确认问题范围；
- `unsupported`：资料直接给出相反规则、状态或机制；
- `insufficient`：资料既不支持也不反驳。
- `not_applicable`：用户任务不是明确的前提核验。

`_is_premise_task()` 先判断问题是否真的要求核验可判真命题。普通比较、总结、建议和“两份资料是否冲突”不属于前提判断 task；即使模型返回 `unsupported`，也会确定性归一为 `not_applicable`，并清空相关来源 IDs 与误报。

“表达绝对”本身不是反证，“可能存在未记载例外”也不能推翻明确制度。supported/unsupported 必须绑定 `premise_source_ids`。Qwen 偶尔把枚举返回成 `{status: supported}`，field validator 会提取枚举值；无法解析时安全降级。

除了大模型审核，程序还固定拒绝不存在的来源编号、无引用声明和未通过 ACL 的证据包。审核员明确否决的声明在回答生成前删除。

## 9. 一次修订

`REVISE` 只有在审核员给出至少一个 `supported=false` 的结构化 `ReviewItem`，或明确标记现有
证据冲突尚未处理时，才让分析员根据 ReviewReport 重写一次。只有笼统 `REVISE`、没有可定位
问题时会归一化为 `PASS`，并在 trace 中记录原始决策和跳过原因。`NEED_MORE_EVIDENCE` 最多再检索
2 个目标查询，然后重写一次。之后调用 `_validate_claims_for_finalization()`：

- 来源编号不存在 → 删除；
- 来源编号为空 → 删除；
- `acl_checked=false` → 删除全部；
- 被删除内容只作为 limitation 数量记录，不进入最终事实。

没有第二轮 Review，所以最大延迟有确定上界，也避免“审核员不满意 → 无限回环”。

这一门槛来自冻结 V2 的失败归因：21 个 `REVISE` 中有 16 个没有任何被拒声明、没有未处理冲突，
`overall_instruction` 也为空，却仍执行了完整分析员修订。按旧 trace 静态计算，这 16 次修订合计
占 89.7 秒、49,046 input 词元和 9,379 output 词元。它只是反事实成本估计，不是新质量结果；
新实现必须在开发集/V3 对照中确认跳过空修订不会降低答案质量。

## 10. 复用回答生成智能体

`deep_research_generation_node()` 不是第四个智能体，它是适配器：

1. 应用审核员明确否决；
2. 再做确定性声明校验；
3. 将证据包映射为 `文档1..n`；
4. 把合法声明映射、前提结论、冲突与局限放进 `retrieval_context`；
5. 调用已有 `generation_agent_node()`；
6. 使用 `config={tags: [user_visible_answer]}` 进入原 SSE；
7. 标记 `used_agent=deep_research`。

回答生成被要求严格输出七段研究简报：

1. 研究问题
2. 已有证据
3. 关键事实
4. 冲突/不确定项
5. 推断
6. 下一步研究建议
7. Sources

事实/比较必须就近 `[文档N]` 引用；推断和建议必须明确标注；无内容写“无”，不能用常识补内部事实。前提结论由适配器确定性加在顶部，避免最终自由生成说丢审核员结果。

普通模式调用同一回答生成智能体时不传格式说明，仍为原 500 字限制；深度研究模式才传研究简报指令和 1400 字上限。因此普通模式行为没有被全局改写。

## 11. 阶段 trace

`research_trace.stages` 记录：

- `researcher`：查询、subquestions、检索 ID/标题、证据包、延迟/调用/词元；
- `analyst`：全部声明、未覆盖 S 编号、证据转声明覆盖率、延迟/调用/词元；
- `reviewer`：完整 ReviewReport、延迟/调用/词元；
- `revision`：修订前后声明、被丢弃声明、最终合法声明、补检索次数；
- `generation`：审核员丢弃项、validated 声明、最终答案、声明引用覆盖、延迟/调用/词元。

它完全落在现有状态/eval JSON 中，没有引入监控平台或消息系统。V2 还增加了 `retrieval | analysis | review | generation | knowledge_gap | acl | none` 统一失败归因，以及查询改写历史、被拒声明原因、修订前后声明和最终有效声明覆盖代理指标。

## 14. 历史盲测 V1 答案级盲评与门禁

每题 B/C 顺序固定随机化为候选甲/乙，先按正确性、完整性、证据依据分别 0～2 打分并落盘，再打开独立映射。未调用额外评分器 API。评分者是本次实现审查者，不是独立第三方人类，这是结果限制；正式大规模上线前建议由课题组成员复核评分表。

| 方案 | 正确性 | 完整性 | 证据依据 | 总分 | 胜出题数 |
|---|---:|---:|---:|---:|---:|
| B 普通模式 | 1.722 | 1.667 | 1.889 | 5.278/6 | 4 |
| C 深度研究模式 | 1.778 | 1.722 | 1.833 | 5.333/6 | 4 |

按类别：

| 类别 | B | C | C 胜出 |
|---|---:|---:|---:|
| false 前提判断 | 5.67 | 6.00 | 1/3 |
| multi 证据 | 5.33 | 5.67 | 1/3 |
| recommendation | 4.67 | 3.67 | 0/3 |
| 研究简报 | 5.33 | 4.67 | 0/3 |
| supported 前提判断 | 6.00 | 6.00 | 0/3 |
| temporal conflict | 4.67 | 6.00 | 2/3 |

预先门槛要求至少一个类别 C 高 1.0/6 且胜 2/3；全集正确性/证据依据不得回退 0.2；前提自动准确率不得低于 B；18 条必须全成功、ACL=0。`temporal_conflict` 满足类别门槛，其他安全门槛也通过，所以显式深度研究模式开放。

该结论现仅是 V1 历史决策证据，不得当作 V2 生产门禁已通过。V2 已证实 H08/H16 对应的 Nu、Quicksand、Argo、AIFM 根本不在 40 文档片段 / 18 文档的 Chroma 快照中，归因为 `missing_document`，不是多智能体角色不够。禁止用第四智能体、动态协商或新基础设施掩盖证据缺口。

## 16. 当前限制

1. 深度研究模式 P50 约为普通模式 3.6 倍，只适合显式复杂任务。
2. 检索没命中目标论文时，多智能体无法补证据；必须诚实写缺口。
3. 关键词、引用覆盖和支持度都是自动代理指标。
4. 当前盲评不是独立领域专家评审。
5. 前端已增加最小的“普通 / 深度研究”选择；默认普通，仅对当前一次请求生效，发送、刷新和新会话后都恢复普通。
6. `is_complex_research_task()` 仅作为离线/诊断窄规则，不参与显式深度研究模式路由。
7. 非前提任务的多余“前提核验”已用四态边界修复；但 V2 盲测明确前提判断任务的自动准确率仅 0.167，这是当前不可掩盖的安全限制。

## 17. 防止过度设计的维护规则

- 普通模式永远是默认；
- 深度研究模式只由显式字段进入；
- 固定三角色，不加第四角色；
- 审核员最多一次修订；
- 不因单题失败增加循环；
- 不改变 ACL、向量表示、重排模型、切块、模型和检索框架；
- 新问题先定位到资料研究员/分析员/审核员/回答生成哪一阶段，再决定是否修；
- 新版本必须使用新留出集，不能对本轮盲测留出集调参。
