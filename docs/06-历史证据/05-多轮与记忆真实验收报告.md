# 实验室科研助手多轮与记忆真实验收报告

> 历史证据：本文记录一次真实验收快照。文末的 P1/P2 建议已经归档，不是当前待办。

## 1. 结论

本轮完成了当前计划中的两个 P0 收尾项：

1. 使用真实 Chromium 浏览器运行 8 组冻结的多轮科研问答样本；
2. 使用真实浏览器和真实 Mem0 完成“确认事实、跨会话召回、撤销、不再召回”闭环。

结果表明，当前多 Agent 主链在实验室知识问答场景下已经可用：普通问题只经过确定性路由、检索与生成，Deep Research 仍由用户显式选择；没有为了评测继续增加 Agent、数据库、中间件或隐藏工作流。

本轮唯一新增的产品能力是“撤销已确认记忆”。这是现有记忆生命周期缺失的一环，不是新架构。除此之外，没有扩展账号、登录或非核心页面。

当前状态：

- P0-1 多轮 Browser Acceptance：完成；
- P0-2 Memory E2E：完成；
- ACL 降权 Recall Gate：自动化集成测试通过；
- Qwen Judge：已完成；
- Codex 模型模拟校准：已完成；
- 独立真人 Calibration：仍为 Pending，不能把模型模拟写成人工评分。

## 3. 多轮真实浏览器验收

### 3.1 样本选择

从冻结数据集选择 8 组代表样本，覆盖四种核心情况：

- 代词指代：`mt-pronoun-01`、`mt-pronoun-03`；
- 省略式追问：`mt-followup-01`、`mt-followup-04`；
- 跨资料比较：`mt-compare-01`、`mt-compare-02`；
- 无需改写的显式问题：`mt-explicit-02`、`mt-explicit-08`。

每组按以下顺序执行：

```text
登录
→ 点击新建会话
→ 输入首轮问题
→ 等待流式回答结束
→ 输入追问
→ 获取服务端历史记录
→ 核对最终 Agent 与引用来源
→ 删除该测试会话
```

验收脚本不会新造测试问题，也不会修改知识库。脚本增加了登录/会话切换等待、逐例检查点和 P50/P95 统计，避免把旧会话消息误算为新回答。

## 4. 长期记忆真实闭环

### 4.1 测试事实

选择一个已经真实完成、Reviewer 决策为 `PASS` 的 Deep Research Run，其中未确认的事实 Claim C3 为：

> 所有正式开展课题的成员及新成员入组初期均需参与组会汇报，缺席需补交书面汇报。

该 Claim 引用了两条当前可访问证据：

- 实验室组会制度与汇报要求；
- 实验室考勤与请假制度。

因此它满足现有 Promotion Gate：Research Run 已完成、Reviewer PASS、Claim 类型为 fact、来源完整、ACL 复核通过，并由用户在页面显式确认。

### 4.2 确认与写入

在页面中展开 Research Run，定位该事实并点击“确认并记住”：

- `POST /api/v1/research/runs/{run_id}/claims/C3/confirm-memory` 返回 200；
- Mem0 使用 `infer=false` 精确存储 Claim，没有让模型再次改写事实；
- 向量写入真实 `mem0_memories` collection；
- 数据库记录用户确认、Research Run、Claim、Source IDs 和 Mem0 memory ID；
- 页面状态变为“已记住（点击撤销）”。

### 4.3 跨会话召回

新建独立会话并输入：

```text
还记得我确认的组会参与要求吗？只回答该要求。
```

真实页面结果：

- Agent：辅助，即 `general_agent`；
- 延迟：3.45 秒；
- 回答与确认事实一致：正式开展课题的成员和新成员入组初期需参与组会汇报，缺席需补交书面汇报。

该结果验证了完整调用链：

```text
新会话问题
→ 用户级 Mem0 向量检索
→ Confirmed Research Fact 元数据检查
→ Research Run / Claim / Source / 当前 ACL 二次验证
→ 允许注入 General Agent 上下文
→ 输出回答
```

### 4.4 撤销与不再召回

原页面此前只有“确认并记住”，确认后按钮永久禁用，无法完成生命周期闭环。本轮进行了最小修复：

- 已确认事实显示“已记住（点击撤销）”；
- 点击后调用同一路径的 `DELETE` 方法；
- 服务端从原确认结果中只提取明确的 Mem0 memory ID；
- Mem0 删除前仍核对 memory 的用户归属；
- 删除用户确认记录，使 Recall Gate 立即失效；
- 即使外部向量存储短暂异常，未确认事实也不会继续注入回答。

真实浏览器撤销结果：

- 撤销请求返回 200；
- 页面按钮恢复为“确认并记住”；
- 对应确认记录数量变为 0；
- Mem0 用户记忆总数从 9 变为 8；
- 目标 memory ID 不再存在，也不再出现在语义检索结果中。

再次新建会话，输入完全相同的问题，页面在 1.91 秒后回答：当前对话历史中未找到用户明确确认的具体内容。该测试会话随后被精确删除。

### 4.5 ACL 降权门禁

针对性集成测试构造了带 `restricted` Evidence 的 Research Fact：

1. 同一用户以 PI 身份完成 Research Run 并确认事实；
2. PI 身份下 Recall Gate 允许召回；
3. 同一用户名降为 student；
4. 历史 Run 壳仍属于本人，但 restricted Evidence 被当前 ACL 隐藏；
5. `validate_confirmed_research_memory` 返回 false，Mem0 候选不能进入 Agent 上下文。

这项验证直接覆盖服务端门禁与真实 SQLite 结构，但没有为了演示而修改当前管理员账号角色。后续如有第二个真实测试账号，可以补一条浏览器级角色切换回归；它不阻塞当前 P0 收口。

## 5. 实现范围

本轮代码只涉及以下边界：

- `tests/eval/run_multiturn_browser_acceptance.py`：稳定运行 8 组真实浏览器样本，逐例保存检查点并统计延迟；
- `src/api/services/research_service.py`：按当前用户读取确认记录中的精确 memory ID，并撤销确认；
- `src/api/controllers/research_controller.py`：增加事实记忆撤销接口；
- `frontend/src/App.vue`：把现有确认按钮改为确认/撤销双态；
- `tests/test_research_workspace.py`：覆盖真实 Mem0 返回结构、精确 ID 删除和撤销后 Recall Gate 失效。

没有新增 Agent，没有新增数据库表，没有接 Redis，没有引入新向量库，也没有改变普通问答与 Deep Research 的路由边界。

## 6. 当时判断与后续建议（已归档）

多轮问答和 Evidence-backed Memory 已具备面试中可清楚解释、可运行演示、可由自动测试复现的闭环。继续调整登录、增加 Agent 数量或搭建新评测平台，当前收益都低于成本，应停止。

当时曾建议进入 P1：Verified Knowledge Promotion。该建议已经归档；当前不因这份历史报告继续扩展项目级知识系统，项目知识能力以现有代码和最新评测说明为准。Mem0 是用户级辅助召回，不能表述为自动学习。

在实现 P1 前不需要再重构多 Agent 主图。独立真人 Calibration 有资源时再补，不应伪造“人工评分已完成”。
