# 实验室科研助手真实产品验收报告

> 历史证据：本文记录早期端到端验收和当时故障修复。文末的 P1/P2 建议已经归档，不是当前待办。

## 1. 验收结论

本轮通过真实 Chromium 浏览器完成登录、点击、新建会话、键盘输入、普通问答、多轮追问、Deep Research 和 Research Run 展开检查。验收重点是科研知识问答主链路，而不是继续扩展账号系统或重做界面。

结论如下：

- 登录与前后端连接正常，前后端一体页面可通过 `http://127.0.0.1:8010` 使用。
- 普通 RAG 能检索实验室资料、生成回答并展示 5 条来源卡片。
- 发现并修复了多轮资料追问被误路由到 Operation Agent 的核心问题。
- Deep Research 能完整运行 Researcher → Analyst → Reviewer → 一次受限修订，并在页面展示结构化 Research Run。
- 修复了 Qwen Reviewer 使用 `review_items`、省略顶层 `decision` 或条目 `supported`、返回 `missing_claim_from_evidence` 时的兼容问题。
- 修复了当前 mem0 版本下单条记忆更新、删除实际失败的问题。
- 修复了 SSE 事件跨网络分块时可能丢失 token、来源或 Research Run 编号的问题。
- 删除了 Vite 默认图标引用，消除页面唯一的静态资源 404。

本轮没有增加 Agent、消息协议、缓存或新基础设施，也没有修改登录产品形态。

## 2. 真实测试环境

- 日期：2026-09-03
- 浏览器：Playwright 驱动的本机 Chromium
- 浏览器操作：真实 `click`、`fill`、`press("Enter")`
- 页面：后端 8010 端口托管的前后端一体构建
- 模型与检索：项目当前 Qwen 配置、混合检索、Qwen Rerank
- 知识库：启动日志确认 40 个文档块
- 隔离方式：每轮创建独立验收会话，完成后只删除该验收会话

复测阶段临时通过进程环境关闭 Mem0 自动写入，避免重复测试问题形成长期记忆；仓库默认配置仍保持 Mem0 开启。首次验收产生的两条测试记忆已通过会话元数据精确删除。

## 3. 首次验收发现的问题

### 3.1 多轮资料追问误入工具执行分支

测试对话：

1. `RDMA 实验前必须记录哪些环境信息？请依据实验室资料回答。`
2. `它还要求做哪些基准测试？只补充上一轮没有说清的部分。`

首轮结果正常：

- Agent：资料检索
- 来源：5 条
- 响应时间：约 8.95 秒

第二轮错误结果：

- 被路由为 Operation Agent
- Operation ReAct 循环达到 LangGraph 25 次递归限制
- 页面直接显示内部 `GRAPH_RECURSION_LIMIT` 异常

根因不是模型能力，而是确定性路由规则把所有包含“上一、刚才、之前”的请求都发送给 Operation Agent。这条规则同时绕过了项目已经存在的 `StandaloneQueryRewriter`，使多轮指代评测能力没有真正接到产品入口。

### 3.2 Reviewer 结构化结果兼容不足

首次 Deep Research 中，Qwen 返回了 `review_items`，但没有返回顶层 `decision`。后续复测还观察到条目省略 `supported`、使用 `missing_claim_from_evidence` 的情况。旧 `ReviewReport` 无法解析这些安全含义明确的变体，因此触发安全降级。首次降级后的受限修订没有保住合法声明，最终页面显示 6 条证据但 0 条声明。

### 3.3 Mem0 单条更新和删除与安装版本不兼容

本机 mem0 的实际接口为：

- `Memory.update(memory_id, data)`
- `Memory.delete(memory_id)`
- `Memory.delete_all(user_id=...)`

旧代码向单条更新和删除额外传入 `user_id`，会得到 `unexpected keyword argument 'user_id'`。这意味着用户纠正或撤回单条记忆时实际失败。

### 3.4 非核心页面噪声

前端模板仍引用不存在的 `/vite.svg`，浏览器控制台产生一次 404。该问题不影响业务，但删除模板残留即可解决，不需要设计新图标系统。

### 3.5 SSE 半行被静默丢弃

最终 Deep 复测中，后端已经完成请求并保存 Research Run，但页面没有出现“查看研究过程”按钮。检查前端发现流读取器假设每个网络 chunk 都以完整 SSE 行结束；当 `research_run_id` 或其他事件被拆到两个 chunk 时，两边都会 JSON 解析失败并被静默忽略。

## 4. 实施的最小修复

### 4.1 路由边界

`src/agent/agents/planner.py` 不再把泛化的历史词直接路由到工具 Agent：

- “它还要求……”“那……”“上一轮没有说清……”等资料追问默认进入 Knowledge Agent。
- Knowledge Agent 继续复用现有最近消息和摘要，由 `StandaloneQueryRewriter` 生成独立检索问题。
- 只有明确询问个人历史、关注点或偏好的表达进入 General Agent，并使用已有摘要与 Mem0 上下文。
- 时间和算术仍进入 Operation Agent，原有产品边界不变。

### 4.2 错误边界

Operation Agent 的未知异常仍完整写入服务端日志，但用户页面只收到简短、可操作的失败提示，不再暴露服务器路径、依赖名和递归堆栈。

### 4.3 Qwen Reviewer 兼容

`ReviewReport` 同时接受 `items` 和 `review_items`。当模型省略 `decision` 时默认使用 `REVISE`；问题条目省略 `supported` 时默认使用 `false`；`missing_claim_from_evidence` 归一化为现有的 `citation_gap`。三项默认值都朝安全方向收敛：最多执行现有的一次受限修订，不会把未经复核的声明误判为通过。

对于 Qwen 自由生成的细粒度 `issue_type`，系统不再维护不断增长的字符串白名单，而是按 `claim/source/evidence/conflict/premise/acl` 语义收敛到现有八类；无法识别的类型统一按 `unsupported` 处理。模型只给 `claim_id` 时，从本轮 `AnalysisReport` 回填原声明文本，Reviewer 仍不能创建新事实。

### 4.4 Mem0 兼容

单条更新和删除改为当前 mem0 1.x 的实际签名，并通过 `asyncio.to_thread` 避免同步存储调用阻塞事件循环。由于 mem0 单条接口本身不接收 `user_id`，调用前先读取记录并核对用户归属，避免跨用户修改；用户级批量删除仍保留 `user_id` 约束。

### 4.5 SSE 流边界

前端流读取器现在保留每个 chunk 末尾的半行，只解析已经收到换行符的完整 SSE 事件，并在流关闭时处理最后一行。协议、后端和页面组件均未改变。

## 5. 修复后的真实浏览器结果

### 5.1 普通问答和多轮追问

首轮：

- Agent：资料
- 回答长度：721 字符
- 来源卡片：5 条
- 响应时间：约 4.73 秒
- 回答覆盖网卡、CPU、内核、NUMA 拓扑、线程绑定和网络拓扑等环境信息

追问：

- Agent：资料
- 回答长度：514 字符
- 来源卡片：5 条
- 响应时间：约 6.21 秒
- 正确继承 RDMA 上下文，补充单连接延迟、多连接吞吐、消息大小曲线、扩展性、NUMA 策略对比和长尾延迟等测试
- 未调用 Operation Agent，未出现递归异常

这证明修复接通了“产品入口路由 → 多轮指代改写 → 混合检索 → Rerank → 有来源回答”的完整链路，而不仅是让一个孤立单测通过。

### 5.2 Deep Research

问题一：`设计一个最小对照实验，验证 RDMA 延迟差异是否来自跨 NUMA 路径。请明确变量、证据和判定标准。`

结果：

- Agent：深研
- 响应时间：约 48.92 秒
- 最终回答长度：1868 字符
- 页面来源卡片：5 条
- Research Run 状态：`completed`
- EvidencePackage：6 条证据
- AnalysisReport：8 条声明
- ReviewReport：`REVISE`
- Research Run 可正常展开，无加载错误

中间复测已经从首次的“6 条证据、0 条声明”恢复到 8 条经过最终确定性引用校验的声明，但后端仍记录了条目字段变体导致的安全降级。该结果证明固定团队的降级边界有效，但不作为兼容完成证据。

最终协议诊断使用更短但语义相同的问题：`依据实验室资料，设计验证 RDMA 跨 NUMA 延迟差异的最小实验。`

- 浏览器完成时间：约 52.31 秒
- 原始 SSE：291 个 `llm_token`、1 个 `research_run_id`、1 个 `sources`、1 个 `used_agent` 和 1 个 `done`
- DOM 中 Research Run 按钮：1 个
- Run 状态：`completed`
- EvidencePackage：7 条证据
- AnalysisReport：7 条声明
- ReviewReport：`REVISE`，1 条结构化复核意见
- `reviewer_call_failed`：`false`

最终结果证明 Reviewer 使用的是真实结构化输出而不是安全 fallback，同时跨 chunk 的 Research Run 事件能稳定进入消息对象。`REVISE` 不是运行失败，而是 Reviewer 要求固定团队执行一次受限修订；页面最终输出已经完成。

本题的声明类型主要是研究建议和实验设计，因此没有出现“确认并记住”按钮。这符合当前规则：只有 Reviewer 最终通过的 `fact` Claim 才允许用户显式提升为长期科研事实，不能为了测试按钮而自动写入记忆。

## 6. 自动测试

新增或更新的回归覆盖：

- 资料型多轮追问必须路由到 Retrieval Agent。
- 明确的个人历史问题路由到 General Agent。
- Operation Agent 未知异常不得出现在用户回答中。
- `review_items` 且无 `decision` 的 Qwen 输出必须安全解析为 `REVISE`。
- Mem0 单条更新和删除必须使用本机 1.x 接口签名。
- 前端构建必须通过，并通过真实 Deep 请求确认 Research Run 事件不再因拆包丢失。

最终全量测试共 340 项通过；前端类型检查和生产构建通过。唯一警告来自 jieba 依赖仍使用已弃用的 `pkg_resources`，与本轮功能无关。

## 7. 当前剩余问题与优先级

### 历史 P1：继续做小规模真实多轮集回归

当前已证明一个 RDMA 追问链路修复。下一步只需从已经冻结的 24 条多轮指代集选取 6 至 8 条代表问题，真实运行并记录路由、来源命中和延迟，不需要建设新的评测平台。

### 历史 P1：补一次“事实声明确认并记住”真实验收

选择明确产出 `fact` 且 Reviewer 为 `PASS` 的问题，验证按钮、写入元数据、跨会话召回和撤回。必须使用专用测试用户或可精确清理的会话，避免污染当前管理员长期记忆。

### 历史 P2：观察外部模型偶发长尾

复测期间有一次普通请求在 120 秒内没有完成，随后立即重试在 4.73 秒完成。后端没有应用异常，判断为外部模型或 Rerank 请求的偶发长尾。当前样本不足以增加复杂重试、熔断或缓存；先在后续真实回归中记录超时比例。

### 历史 P3：MCP 关闭日志

前台进程收到 Ctrl+C 后服务能完成关闭，但 MCP stdio 依赖偶尔输出 AnyIO cancel scope 日志。它不影响正常请求和进程退出，当前不值得围绕第三方关闭行为改造主架构。

## 8. 是否应该停止继续改造

架构层面应停止扩展：当前固定 Research Team、一次修订上限、结构化证据与声明协议已经足够支撑秋招讲解。下一阶段的收益来自小样本真实验收和面试材料整理，而不是继续增加 Agent。

可以继续的工作应严格限定为：真实测试发现可复现的核心错误、已有评测集的代表性复跑，以及把“为什么普通问题单 Agent、复杂研究才多 Agent”讲清楚。登录、Redis、动态 Supervisor、Agent 市场和 UI 重构都不应进入近期范围。
