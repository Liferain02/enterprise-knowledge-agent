# 真实浏览器长期产品审查目标

## 目标

持续以真实用户方式审查并提升 `enterprise-knowledge-agent`：每轮从可复现的本地状态启动后端与前端，主聊天模型使用项目原有的 Qwen；通过真实 Chromium 页面使用鼠标点击、键盘输入、滚动、页面切换和文件选择，覆盖核心用户旅程与异常情况。以页面表现、网络请求、服务日志和数据状态作为证据，每轮只修复一个直接改善科研知识闭环的高价值小问题，并用同一路径重新启动、复测和回归。

## 每轮循环

1. 确认工作区改动，保留用户已有内容；检查端口、配置和数据状态。
2. 启动 FastAPI 与 Vue，验证 `/health` 和首页可访问。
3. 使用浏览器执行本轮场景，不以直接调用 API 代替 UI 操作。
4. 同时收集截图、浏览器 console、失败请求、后端日志和可见数据。
5. 按用户价值、发生概率、严重度、修复成本排序发现。
6. 每轮只选择一个问题：先留下可复现步骤或测试，再做低耦合、可回滚修复。
7. 重启服务并重复原浏览器路径；随后运行相邻测试、后端全量测试、前端构建及适用的 RAG 评测。
8. 在持续审查日志记录发现、暂缓项、改动和验证证据，然后进入下一轮。

## 场景池

- 首次打开、错误登录、正确登录、退出、刷新后恢复。
- 空输入、正常问题、无答案问题、连续追问、长问题、取消生成、模型或网络异常。
- 回答正文、Agent 标识、引用来源、历史会话、反馈提交与知识缺口状态。
- 资料目录、筛选、搜索、上传、重复文件、错误格式、入库状态与失败重试。
- 科研项目、成员、实验记录、组会待办的浏览、创建、校验和状态更新。
- 管理员与普通成员的数据范围；只有发现明确越权时才深入认证实现。
- 刷新、快速连续点击、多标签页、窄屏和横向溢出。

并非每轮穷举全部场景；核心旅程每轮必测，其余按风险轮换，避免为了覆盖率堆测试。

## 优先级边界

1. 资料入库、检索、可信回答和来源追溯。
2. 反馈驱动的知识补全。
3. 项目、实验与组会协作记录。
4. 明确影响使用的性能、恢复和移动端问题。
5. 登录、MCP、多 Agent 和基础设施只在阻断使用、明确越权或数据丢失时优先。

不新增没有明确需求的服务、框架、Agent、抽象层或观测平台；不因为代码“看起来不够优雅”而重构。

## 配置与凭据

- 主聊天模型：项目原有 Qwen 模型，与 embedding、reranker 和视觉能力使用同一 DashScope 配置。
- API Key 不进入文档、截图、测试报告、命令输出或 Git diff。
- 本地密钥只保存在被 Git 忽略的 `config/.env`。

## 结束条件

同时满足以下条件后才结束：

- 连续两轮完整浏览器巡检没有发现 P0/P1 核心缺口。
- 登录、对话、连续追问、引用、资料目录/筛选/入库、反馈、科研项目/实验/待办和刷新恢复均通过。
- 不同权限的关键数据范围通过。
- RAG 评测集与当前实验室资料一致并达到已记录门槛。
- 后端全量测试、前端构建以及适用的质量门禁全部通过。

结束时只汇总剩余 P2/P3 建议，不为了清零低价值问题继续设计。
