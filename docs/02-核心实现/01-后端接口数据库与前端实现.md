# 后端接口、数据库与前端实现

本文从工程实现角度说明 FastAPI、数据持久化和 Vue 单页应用如何协作。接口的实时可执行定义以服务启动后的 `/docs` OpenAPI 页面为准，本文负责解释设计语义和代码位置。

## 1. 后端分层

```text
main.py
  ├─ Middleware：异常、限流、输入安全、CORS
  ├─ Controller：HTTP 参数、认证依赖、响应模型
  ├─ Service：业务流程、ACL、事务边界
  ├─ Repository/DAO：SQLite CRUD
  ├─ Agent/RAG：推理与检索
  └─ Storage：Chroma、版本库、任务队列
```

Controller 不应直接拼 SQL 或实现检索算法；Agent 也不应直接处理 HTTP。当前主要边界是：

- `src/api/controllers`：协议适配；
- `src/api/services`：应用业务；
- `src/api/repositories/dao`：会话与反馈持久化；
- `src/agent`：对话决策；
- `src/rag`：知识生命周期；
- `src/api/security_user.py`：用户认证数据；
- `src/api/database.py`：更广的实验室权限/审计基础表，部分能力属于兼容或扩展基础。

## 2. 应用启动与生命周期

根目录 `main.py` 创建 FastAPI 应用。lifespan 启动阶段依次：

1. 初始化 MCP 客户端与受限文件系统工具；
2. 检查 Chroma 集合但不阻塞式重建；
3. 在后台线程启动入库 Worker；
4. 对外提供 API。

关闭阶段停止 Worker、关闭可选 Redis 连接并关闭 MCP。异步 LangGraph checkpoint 在 FastAPI 事件循环内创建，避免 SQLite 连接跨事件循环。

若 `frontend/dist` 存在，后端还会在 `/` 托管打包后的前端，并挂载 `/static`。开发模式则由 Vite 单独提供页面并把 `/api` 代理到后端。

## 3. 接口总表

### 3.1 健康检查

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 汇总向量库、Redis 等组件状态；可选组件异常时可能是 degraded |
| GET | `/health/live` | 进程存活探针 |
| GET | `/health/ready` | 核心依赖就绪探针 |
| GET | `/api/v1/health` | 对话模块简要健康状态 |

### 3.2 认证

前缀：`/api/v1/auth`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/register` | 注册数据库用户，密码存储为 Argon2 hash |
| POST | `/login` | 验证用户并签发 JWT |
| GET | `/me` | 返回当前用户与最新角色信息 |

JWT 使用 HS256。认证开启时，配置层会拒绝过短 JWT secret 和弱管理员密码。旧密码 hash 登录成功后可升级到新 hash。Token 包含认证来源，但每次授权仍刷新数据库角色，支持撤权及时生效。

### 3.3 对话与会话

前缀：`/api/v1`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/chat` | 非流式问答 |
| POST | `/chat/stream` | SSE 流式问答，生产前端主路径 |
| GET | `/history/{session_id}` | 获取当前用户的会话历史 |
| DELETE | `/history/{session_id}` | 删除历史消息 |
| GET | `/sessions` | 列出当前用户会话 |
| POST | `/sessions` | 新建会话 |
| PUT | `/sessions/{session_id}/title` | 修改标题 |
| DELETE | `/sessions/{session_id}` | 删除会话及关联内容 |

Service 使用 `_make_session_id(user_id, session_id)` 生成内部键并转义分隔符，避免不同用户选择相同前端会话 ID 时相互访问。

两个聊天接口的请求都支持：

```json
{
  "message": "用户问题",
  "session_id": "会话 ID",
  "research_mode": "normal"
}
```

`research_mode` 只接受 `normal | deep`，省略时为 normal。Deep 必须由调用方显式选择；它进入固定 Researcher → Analyst → Reviewer → 最多一次修订，再复用既有 Generation Agent。服务端配置 `DEEP_RESEARCH_ENABLED=false` 时会明确返回“尚未通过/已关闭生产门禁”，不会静默降级或自动换模式。当前前端未增加开关，API 调用方可使用该字段。

### 3.4 知识库

前缀：`/api/v1/knowledge`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/add` | 添加文本知识 |
| POST | `/add/file` | 上传文件并提交异步任务 |
| POST | `/search` | 权限感知的知识检索 |
| GET | `/stats` | 向量库统计 |
| GET | `/overview` | 当前用户可见知识概览 |
| GET | `/documents` | 按逻辑源文件列出文档 |
| GET | `/ingestion/jobs` | 最近入库任务 |
| GET | `/ingestion/jobs/{job_id}` | 单任务状态 |
| DELETE | `/documents` | 按 source 删除文档 |
| POST | `/seed-lab-samples` | 写入示例资料 |
| DELETE | `/clear` | 清空集合，高权限操作 |

上传、删除、清空和示例初始化都受角色限制。列表与搜索结果按当前用户 ACL 收敛，不应把管理端完整统计直接当成普通用户可见数量。

### 3.5 科研工作区

前缀：`/api/v1/research`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/overview` | 用户可见项目、实验、任务汇总 |
| POST | `/seed-samples` | 初始化示例科研数据 |
| GET/POST | `/projects` | 列表或创建项目 |
| GET | `/projects/{project_id}` | 项目详情 |
| GET/POST | `/projects/{project_id}/experiments` | 实验记录列表或创建 |
| GET/POST | `/projects/{project_id}/tasks` | 任务列表或创建 |
| POST | `/projects/{project_id}/tasks/extract` | 从文本提取任务 |
| PATCH | `/tasks/{task_id}` | 修改任务状态等字段 |

项目的 `visibility`、成员表和角色共同决定可见性；实验与任务继承项目边界。文本提取只是提高录入效率，最终结构化数据仍在服务端校验。

### 3.6 用户反馈

前缀：`/api/v1/feedback`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/feedback` | 提交点赞、点踩或文字反馈 |
| GET | `/feedback/stats` | 审核者查看统计 |
| GET | `/feedback/issues` | 查看待处理问题 |
| PATCH | `/feedback/issues/{feedback_id}` | 标记处理状态与处理说明 |

反馈记录保存原问题、回答、使用 Agent 和处理状态，目标是形成知识缺口闭环，而不只是展示一个满意率数字。

### 3.7 视觉、A2A、WebSocket

- `/api/v1/vision/health`、`/understand`、`/describe`：可选视觉理解；
- `/.well-known/agent.json`：A2A Agent Card；
- `/api/v1/a2a/send`、`/api/v1/a2a/tasks/{id}`、`/api/v1/a2a/skills`：机器任务协议；
- `/ws/chat`：WebSocket 兼容通道。

当前浏览器主链是 JWT + SSE。WebSocket 的认证实现相对简化，生产部署若要启用高权限操作，应先补齐与 HTTP 相同的 token 验证，而不是默认两者安全等级相同。

## 4. SSE 事件协议

流式响应的媒体类型是 `text/event-stream`。典型事件语义包括：

| 事件数据 | 前端行为 |
|---|---|
| 增量内容 | 追加到当前助手气泡 |
| thinking/status | 展示检索、生成、工具或 Deep 的 Researcher/Analyst/Reviewer/一次修订阶段 |
| sources | 渲染来源卡片 |
| version_source | 展示文档版本溯源 |
| used_agent | 展示实际分支标签 |
| error | 停止加载并显示错误 |
| done | 收尾、刷新会话列表 |

ChatService 是事件过滤边界：嵌套 LLM、grader 和内部工具事件默认不直接暴露。Generation Agent 通过标签标识用户可见输出，避免内部模型调用也被当成 token 流。

新增事件时应先保持旧前端可忽略未知字段，再同步更新 TypeScript 解析逻辑和流式测试。

## 5. 数据库存储地图

项目采用“按职责分库”的本地持久化，便于单机部署和故障隔离。

| 路径 | 类型 | 主要数据 |
|---|---|---|
| `chroma_db/` | Chroma | `lab_knowledge` 文档向量与元数据 |
| `chroma_db/sessions.db` | SQLite | `sessions`、`messages`、`feedback` |
| `chroma_db/langgraph_checkpoints.db` | SQLite | 异步 LangGraph thread 状态 |
| `data/users.db` | SQLite | 用户、角色、用户角色和权限 |
| `data/research_workspace.db` | SQLite | 项目、项目成员、实验、科研任务 |
| `data/ingestion_queue.db` | SQLite | 入库任务、重试和结果 |
| `data/document_versions.db` | SQLite | 文档版本、当前版本和状态 |
| `data/lab_assistant.db` | SQLite | 更广的部门、权限、文档和审计基础结构 |

具体路径可由 Settings 改变，表中是默认布局。

### 5.1 会话与反馈

`SessionDAO` 创建：

- `sessions(session_id, title, created_at, updated_at, message_count, metadata)`；
- `messages(id, session_id, role, content, created_at, metadata)`；
- `feedback(...)`，并在启动时为旧数据库补字段。

SessionService 封装用户隔离、自动建会话、首条消息标题和删除事务。标题采用确定性截断生成，不额外调用 LLM。

### 5.2 用户与角色

`src/api/security_user.py` 管理 `data/users.db`。账号密码绝不以明文存储。默认管理员只用于配置引导；生产环境必须覆盖默认凭据。

### 5.3 科研工作区

`ResearchService` 自初始化四张核心表：

- `research_projects`；
- `research_project_members`；
- `research_experiments`；
- `research_tasks`。

SQLite 外键在每个连接上显式开启。Service 统一 commit/rollback，确保异常时不留下半条业务记录。

### 5.4 Checkpoint 与聊天记录的区别

Checkpoint 保存 Agent 工作流状态，便于同一 thread 延续；聊天记录保存产品需要展示的稳定消息。同步测试使用 `MemorySaver`，FastAPI 异步服务可使用 `AsyncSqliteSaver`。不能用 checkpoint 数据直接替代可审计聊天历史。

## 6. 前端结构

前端使用 Vue 3、TypeScript 和 Vite。当前规模下主要 UI 逻辑集中在 `frontend/src/App.vue`，全局视觉与响应式规则在 `frontend/src/style.css`，入口是 `frontend/src/main.ts`。

### 6.1 三个产品工作区

1. 对话工作区：会话列表、流式问答、停止生成、来源、版本和反馈；
2. 知识工作区：概览、文档筛选、上传、入库状态轮询和搜索；
3. 科研工作区：项目、实验、任务及文本任务提取。

登录/注册后 JWT 保存在浏览器本地存储，请求统一附加 Authorization。401 时应清理失效身份并返回登录态。

### 6.2 对话状态

核心状态通常包括：当前会话、消息列表、正在流式生成的消息、来源、所用 Agent、请求取消器和错误信息。发问时先插入用户消息与空助手消息，收到 token 后增量更新，done 后刷新会话元数据。

来源卡片和版本信息是回答的附属结构，不能拼接进正文后再靠字符串解析。

### 6.3 知识管理状态

上传成功只表示任务已提交。前端根据 job ID 轮询状态，并区分 completed、retrying 与 failed。文档列表按 source 聚合，搜索结果则是按相关性返回的内容片段，两者含义不能混用。

### 6.4 响应式布局

样式针对窄屏收起或重排侧栏、卡片和操作区，目标是在约 390px 宽度下不产生页面级横向滚动。修改长文件名、代码块和来源链接样式时，需特别检查 `overflow-wrap` 和内部滚动。

## 7. 安全实现

### 7.1 输入安全

`InputSecurityMiddleware` 检查 SQL 注入、XSS、提示注入、零宽字符、路径和 PII 等模式。安全检查分两类：

- 明确恶意或危险输入可拒绝；
- 可疑自然语言应记录或清理，避免误伤正常科研内容。

检索到的文档还会在生成提示中被标记为不可信数据，防止文档中的“忽略以上指令”劫持 Agent。

### 7.2 限流

默认按分钟限制普通、匿名、聊天和入库请求，聊天与上传阈值更严格。限流是资源保护，不替代账号权限。

### 7.3 CORS

当前 `main.py` 使用宽松的 `allow_origins=["*"]`，适合内网开发但不是严格公网配置。正式跨域部署应配置明确来源，并重新核对 credentials 行为。

## 8. 修改接口的标准步骤

新增一个业务接口时，建议顺序为：

1. 在 schema 中定义请求与响应模型；
2. 在 Service 中实现业务与 ACL；
3. 必要时在 DAO 中实现参数化 SQL；
4. Controller 只做协议转换和依赖注入；
5. 注册路由；
6. 增加 service/controller 绑定测试和权限测试；
7. 更新本文接口表与 OpenAPI 说明；
8. 在真实浏览器验证成功、无权限、空状态和失败状态。

避免直接在 `App.vue` 里假设服务端权限，也避免为一个简单字段引入新的服务或数据库。
