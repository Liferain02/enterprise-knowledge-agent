# 知识库扩容与真实端到端验证

> 2026-09-30。新增内容全部为明确标注的合成公开风格练习资料，不包含真实个人信息、密钥或实验室机密。验证使用当前配置的 MySQL、Qdrant、Redis、百炼和本地 reranker；登录凭据从本地配置读取，但不写入报告。

## 1. 扩容结果

历史 `.run/corpus-qwen.json` 快照记录 338 个源文件、1545 个 chunk。当前本地目录原本已有更多 public manuals，但评测报告未覆盖这批新增文件。此次生成 `data/knowledge/synthetic_autumn_2026/` 下 6 类共 240 个合成 Markdown 文件：

- RDMA：队列对、完成轮询、内存注册、RoCE 拥塞、NIC-NUMA、带宽压测。
- NUMA：远程内存、first-touch、页迁移、socket locality、一致性、尾延迟。
- Retrieval：BM25、向量召回、重排、ACL、查询改写、chunk overlap。
- Systems：perf、CPU 绑核、HugePages、容器限制、线程池、checkpoint 恢复。
- Experiments：消融、热缓存延迟、吞吐、故障注入、置信区间、复现性。
- Paper writing：方法、实验表、rebuttal、引用审计、局限性和摘要。

同步计划和应用结果为 **578 个源文件、1785 个 chunk、约 166 万字符**；应用命令使用 `--collection lab_knowledge` 映射到当前 `lab_knowledge_qwen_v1`，避免显式传入旧 collection 名称造成 embedding signature 冲突。服务启动日志随后确认 Qdrant 当前包含 **1785 个文档块**。

这些合成资料用于扩容、权限/分块/检索回归和演示，不可在面试中说成真实科研数据，也不应作为回答实验结论的唯一证据。

## 2. 评测集扩容

秋招展示用 Retrieval Benchmark 从 28 条扩展到 **88 条**：原有 28 条冻结样例保留，新增 6 个合成主题、每类 10 条，包含明确主题、复现条件和限制的查询，并给每条加入两个改写问题。测试契约同步校验 88 条、类别计数、唯一 ID、文档级 gold 和 65 条带改写样例；新增 corpus expansion contract 测试。

88 条仍属于开发/回归集，不是独立盲测；合成查询和合成资料存在同源偏差。下一步应从真实用户问题中脱敏采样，并按时间切分为 dev/holdout，避免继续只增加模板数量。

## 3. 启动与登录验证

`./scripts/start.sh` 第一次在远程命令会话中打印“启动成功”，但后台子进程在会话结束后退出，8010 端口随后不可访问。这是脚本的进程脱离问题，与应用健康状态无关。已在启动脚本加入 `setsid` 优先路径，并保留原有 PID 文件和 `stop.sh` 管理方式。

本次为避免再次受到远程 shell 生命周期影响，使用持久 PTY 前台启动 `main.py`，健康检查返回 `{"status":"ready"}`，启动日志显示 Qdrant 当前包含 1785 个文档块。

实际调用了当前前端使用的 API 登录流程：

```text
POST /api/v1/auth/login
→ GET /api/v1/auth/me
→ POST /api/v1/sessions
→ POST /api/v1/chat
→ POST /api/v1/knowledge/search
```

结果：登录 HTTP 200，`/me` HTTP 200，角色为当前配置管理员；创建会话 HTTP 200；知识检索 HTTP 200、返回 5 条结果。真实对话测试：

1. “实验室组会多久召开一次？”返回 HTTP 200，并引用组会制度和考勤资料，回答每周一次。
2. “根据实验记录计算平均延迟”返回 HTTP 200，但正确指出当前命中的资料是实验规范/要求而非具体测量值，拒绝编造平均值，并提示需要延迟列表或 CSV。

第二个问题暴露了一个有价值的产品边界：知识库扩容后“命中资料”不等于“资料包含可计算数据”。系统应继续区分规范、方法和测量记录；测试不能只检查 HTTP 200，还要检查“缺少数值时不计算”。

本环境没有 Chromium、Playwright、Selenium 或 PyAutoGUI，因此没有伪造“鼠标键盘自动化完成”。实际验证使用前端同源 API 请求，覆盖的登录和聊天接口与 Vue 页面相同；浏览器 UI 自动化需要后续在装有浏览器运行时的环境执行。

## 4. 当前发现与修复

| 发现 | 处理 |
|---|---|
| 启动脚本子进程随远程命令会话退出 | `start.sh` 使用 `setsid` 脱离进程组；本次用持久 PTY 验证服务可访问 |
| Qdrant 应用时报 embedding signature 冲突 | 同步命令改用逻辑 collection `lab_knowledge`，由 settings 映射当前 qwen collection；没有新建错误 collection |
| BM25 原来会漏出 staging/retired | 已修复并有回归测试，扩容后继续复用 active 发布过滤 |
| “根据实验记录计算”没有真实测量值 | 真实对话正确拒绝编造；后续应增加带数值的脱敏实验样例和对应 gold |

## 5. 复现命令

```bash

conda run -n agent-demo python scripts/generate_synthetic_corpus.py

# 先检查 578 份源文件 / 1785 个 chunk，再应用到当前 Qdrant
conda run -n agent-demo python scripts/sync_knowledge_corpus.py \
  --infrastructure --report .run/corpus-synthetic-plan.json
conda run -n agent-demo python scripts/sync_knowledge_corpus.py \
  --infrastructure --apply --collection lab_knowledge \
  --report .run/corpus-synthetic-apply.json

# 评测集契约和全量测试
conda run -n agent-demo python -m pytest tests/test_秋招版检索评测.py -q
conda run -n agent-demo python -m pytest -q

# API 登录/会话/检索/对话烟测（不输出密钥）
conda run -n agent-demo python /tmp/eka_e2e.py
```
