# 技术文档总览

## 1. 文档目的

这套文档描述 `enterprise-knowledge-agent` 仓库当前已经实现的实验室科研智能助手，而不是早期通用知识助手原型，也不是未来路线图。阅读代码时应以本文索引和实际调用链为准；不可达的 Supervisor、并行执行、旧 ReAct、Table QA 和通用答案缓存已完成清理。

文档基线日期为 2026-09-04。当前产品名称为“实验室科研智能助手”，定位为计算机专业研究生实验室内部的科研知识管理、证据检索与协作系统。仓库历史名称不代表产品定位。最终收口后的公开入口以根目录 `实验室科研助手_文档索引.md` 为准。

## 3. 推荐阅读路径

### 3.1 第一次了解项目

1. 阅读《项目定位与总体方案》的产品边界和核心用户旅程。
2. 阅读《系统架构与请求链路详解》的总体架构图和知识问题时序。
3. 浏览《后端接口数据库与前端实现》的 API 总表。
4. 按《启动与远程访问指南》启动并实际操作产品。

### 3.2 接手后端或 Agent 开发

1. 先理解当前 LangGraph 只包含一个 Planner 路由器。
2. 再理解 normal 统一执行 Retrieval → Generation，显式 deep 才执行固定三角色链。
3. 阅读《复杂科研多智能体团队实现与评测》，理解一次修订上限、Development/Holdout 隔离和选择性上线结论。
4. 阅读 RAG 分册中的 ACL、Hybrid、Rerank 默认顺序和 CRAG 关闭依据。
5. 阅读代码导航中的状态字段契约、输出契约和测试要求。

### 3.3 调优检索和评测

1. 阅读《知识库入库检索与权限实现》的候选生成与排序阶段。
2. 阅读《评测测试与质量保障》的文档级去重、无答案口径和上下文覆盖指标。
3. 阅读根目录《秋招版评测收口说明》，区分 Retrieval Benchmark、技术分词 POC 和 Knowledge Evolution proxy。
4. 修改评测集或参数时，先建立基线，再修改算法；不要同时改数据、指标和检索器。

### 3.4 部署和排障

1. 使用 `./scripts/start.sh`，不要手工分别启动后端和前端。
2. 先检查服务器本机 `127.0.0.1:3000/8010`，再排查 SSH `-L`。
3. 按配置运维分册区分核心依赖和可选依赖；Redis 未配置不是故障。

### 3.5 准备秋招面试

1. 从[秋招面试资料总览](秋招面试/00-阅读导航/00-秋招面试资料总览.md)选择一天、三天或一周路径。
2. 先掌握[项目全景与架构讲解](秋招面试/01-项目与架构/01-项目全景与架构讲解.md)，再按 `02-核心实现` 的编号逐函数跟踪 Normal 和 Deep。
3. 从 `04-技术难点与复盘` 选三个 STAR 故事，并用[高频面试问答手册](秋招面试/05-面试实战/01-高频面试问答手册.md)做限时模拟。
4. 最后根据[简历表达与项目演示](秋招面试/05-面试实战/02-简历表达与项目演示.md)收紧简历，录制一段无凭据、无敏感数据的备用 Demo。
5. 当前没有新的失败证据时停止架构扩张；如需复现实验，直接运行 `tests/eval/` 下的冻结评测脚本。

## 4. 当前请求主链与历史代码

### 4.1 当前请求主链

聊天请求使用以下图：

```text
maybe_summarize
  → retrieve_mem0_memories
  → planner
      ├─ knowledge → retrieval_agent → generation_agent ┐
      ├─ operation → operation_agent                    ├─ finalize_response → END
      ├─ general   → general_agent                      ┤
      └─ explicit deep → researcher → analyst → reviewer
                         → 最多一次 revision → existing generation ┘
```

关键事实：

- `planner` 是唯一请求路由器。
- 知识检索必须经过 ACL 感知的 Hybrid + Rerank 主链；CRAG 默认关闭。
- normal 的复杂科研和前提核验问题仍由 Query Expansion 单 Agent 处理；只在 API 显式 `research_mode=deep` 时进入固定 Research Team。
- 固定团队没有 Supervisor、动态 Worker 或自由循环，Reviewer 最多触发一次修订，最终复用既有 Generation Agent。
- 所有分支都经过统一 `finalize_response`。
- Mem0 写入由 ChatService 在响应后调度，不属于用户响应关键路径。

### 4.2 已删除的伪复杂路径

Supervisor、Parallel Executor、Planner 的 Execute Plan/Send、旧 Knowledge ReAct 包装和
未接入主链的 Query Cache 已删除。它们不再是“兼容代码”，文档和讲解也不应继续暗示
这些能力仍存在。当前代码只保留实际可达、可测试的请求路径。

## 5. 当前技术栈

| 层 | 实现 |
|---|---|
| 前端 | Vue 3、TypeScript、Vite、Axios、Marked、Highlight.js |
| Web API | FastAPI、Uvicorn、Pydantic、SSE；另有可选 WebSocket/A2A 接口 |
| Agent 编排 | LangGraph 1.x、LangChain 1.x |
| 对话模型 | 默认 Qwen，当前运行验证为 `qwen3.5-flash`；支持 OpenAI-compatible 备用配置 |
| Embedding | 与对话模型独立配置，默认 Qwen `text-embedding-v2` |
| 向量库 | ChromaDB，本地持久化集合 `lab_knowledge` |
| 关键词检索 | `bm25s` 优先，`rank_bm25` 备用，Jieba 中文分词 |
| Rerank | Qwen 百炼 `TextReRank`；也保留 FlashRank/BGE 适配 |
| 纠错检索实验 | Corrective RAG 可显式消融，默认关闭，不计入默认主链能力 |
| 业务存储 | 多个职责分离的 SQLite 数据库 |
| 长期记忆 | 对话摘要；Mem0 默认开启，初始化、检索或后台保存失败时降级 |
| 工具协议 | MCP filesystem，作用域限定为 `data/knowledge` |
| 认证 | JWT HS256、Argon2 密码哈希、数据库角色刷新 |
| 测试 | Pytest、pytest-asyncio、真实浏览器巡检、真实检索评测 |

## 6. 当前数据规模与验证基线

截至文档基线：

- 资料中心按来源聚合后为 18 份资料。
- Chroma 中为 40 个检索片段。
- 科研空间样例为 2 个项目、2 条实验记录和 2 条未完成待办。
- V2 冻结验证后端为 272 passed；本轮定位、可信度与模拟盲评协议收口后为 294 passed。历史数字仅作为时间快照。
- 前端 `vue-tsc` 和 Vite 构建通过，共转换 62 个模块。
- 快速真实检索基线中，正常问题 Hit@5 为 100%，NDCG@5 为 0.9167，MAP 为 0.8889，无答案正确拒答率为 100%。
- 41 条 Development Eval V2 中，B Normal 的关键点/引用覆盖/文档召回/premise 为 0.939/0.516/0.632/0.889；Deep 为 0.988/0.677/0.677/0.667，P50 为 28.7 秒对 7.0 秒。
- 18 条 V1 现标记为 Historical Blind Holdout / Regression after inspection，不再用于新的泛化声明。
- 26 条 Blind V2 中，Deep 自动关键点/引用覆盖/文档召回/premise 为 0.913/0.727/0.811/0.167，Normal 为 0.865/0.507/0.679/0.667。Deep premise 违反预声明 safety gate；独立人工盲评待完成，所以尚无 V2 最终产品收益结论。

这些数字是“特定代码、知识库、模型和评测集组合”的快照，不是永久承诺。任何知识库重建、模型切换、Reranker 参数变化都应重新生成基线。

## 7. 文档中的状态标签

为避免把实验代码写成稳定能力，各分册使用以下含义：

- **当前路径**：当前前端和 `/api/v1/chat/stream` 实际调用。
- **可选能力**：配置开启或接口直接调用时才使用，例如 Mem0、Vision、WebSocket。
- **兼容代码**：保留以避免旧导入失效，但不在当前主链。
- **已知限制**：已经确认但尚未影响主路径，或需要产品决策后才能修改。
- **验证基线**：在指定日期、数据和配置上实际运行得到的结果。

## 8. 文档维护规则

1. 所有说明文档使用中文文件名。
2. 协议要求的 `Skill.md`、源码文件和第三方约定不强制改名。
3. 架构变化必须同时更新本索引、架构分册和代码导航。
4. 评测结果必须注明数据集、模型、知识库版本和日期。
5. 不把关键词重叠指标称为 Faithfulness，也不把检索命中等同于最终回答正确。
6. 不记录 API Key、管理员口令、JWT 密钥或用户数据。
7. 代码行号会随编辑变化，因此文档以函数、类和文件路径定位，不依赖固定行号。
