# 实验室科研助手：秋招版评测收口说明

## 1. 目的

本说明记录最终收口阶段新增的两组离线评测，以及它们对架构的实际决策。项目定位是**实验室科研助手**，重点是实验室内部科研资料的可靠检索、有限多智能体研究和受控知识沉淀，不是通用企业知识库，也不是无限扩展的自动化平台。

评测遵循三个约束：固定数据、固定指标、失败驱动。一次结果只描述当前本地 Chroma 快照，不外推为线上质量保证；没有稳定收益的能力不接入默认链路。

## 2. 秋招版 Retrieval Benchmark

### 2.1 数据集

脚本：`tests/eval/秋招版检索评测数据集.py`

冻结集共 28 条文档级 Gold：

| 类别 | 数量 | 观察点 |
|---|---:|---|
| simple_factual | 8 | 普通制度和流程事实 |
| technical_exact_token | 6 | RDMA、`ib_write_bw`、`mlx5_0`、CUDA 等精确词 |
| paraphrase | 5 | 省略、改写和语义稳定性 |
| distractor_heavy | 5 | 相近但错误来源的干扰 |
| multi_document | 4 | 需要多个来源共同覆盖 |

Gold 只使用稳定文档标题，不伪造会随切块变化的 chunk Gold。每条数据显式保存 `distractor_ids`、`paraphrase_queries` 和 `gold_level=document`。

### 2.2 四个对照方案

脚本：`tests/eval/run_秋招版检索评测.py`

1. Dense Only：只使用向量检索。
2. Hybrid + RRF：向量和 BM25 各取排名后用 RRF 融合。
3. Hybrid + Rerank：在 Hybrid 候选上调用现有 Reranker。
4. Current Final：调用当前默认检索入口，按规则选择性触发 Standalone Rewrite 和 Query Expansion。

所有方案都通过统一 ACL 过滤；Current Final 的 `needs_expansion` 使用 `RuleBasedDecomposer.needs_expansion(query)`，避免把“固定关闭扩展”的实验误标为最终链路。

### 2.3 当前快照结果

本地快照为 18 个文档、40 个 chunks。四方案完整运行结果如下：

| 方案 | Hit@1 | Hit@5 | MRR@5 | NDCG@5 | Coverage@5 | Top1 Drift | Regression | ACL | P50/P95(ms) |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Dense Only | 0.786 | 0.964 | 0.869 | 0.819 | 0.869 | 0.455 | 0.091 | 0 | 178/222 |
| Hybrid + RRF | 0.857 | 0.964 | 0.899 | 0.861 | 0.899 | 0.364 | 0.091 | 0 | 183/232 |
| Hybrid + Rerank | 0.821 | 0.893 | 0.838 | 0.797 | 0.833 | 0.364 | 0.091 | 0 | 439/516 |
| Current Final | 0.821 | 0.929 | 0.855 | 0.818 | 0.863 | 0.364 | 0.091 | 0 | 493/1788 |

解读：

- Dense 对普通语义查询可用，但精确技术词和多来源查询仍需要词法信号；Hybrid + RRF 的整体 MRR 比 Dense 高 `0.030`，技术子集 MRR 为 `0.639`，比 Dense 的 `0.556` 更稳。
- Reranker 在本快照没有带来收益：相比 Hybrid + RRF，Hit@5 从 `0.964` 降到 `0.893`，MRR 从 `0.899` 降到 `0.838`，P50 延迟约翻倍。因此不因“有 Reranker”而宣称质量提升。
- Current Final 的选择性扩展改善了覆盖：Hit@5 为 `0.929`，但 P95 受扩展和本地模型调用影响达到约 2 秒级，不能把它描述成低延迟方案。
- 所有方案 ACL violation 均为 0。Paraphrase 的 Top1 Drift 仍存在，说明稳定性应继续被观察，但当前没有证据支持新增 Rewrite Agent。

## 3. Technical-aware tokenizer POC

脚本：`tests/eval/run_秋招版技术分词消融.py`

只在评测进程替换 BM25 tokenizer，比较：

- `current`：现有 `jieba.cut`；
- `search`：`jieba.cut_for_search`；
- `search_technical`：搜索分词加 `[A-Za-z0-9_./-]+` 技术词正则。

技术子集 MRR@5 分别为 `0.639 / 0.639 / 0.639`。任务书预设门槛为至少提升 `0.03`，三者均未达到，因此结论是：**保留当前 tokenizer，停止 P3 技术分词方向，不改线上默认代码**。全量 MRR 的小幅波动不足以推翻该结论。

## 4. Knowledge Evolution 评测

脚本：`tests/eval/知识演化生成评测.py`

冻结 8 个场景，覆盖：新实验结论、Raw 已覆盖、Supersede、Revoke、当前 ACL 不可见、Derived-only、Provenance 和项目事实复用。对照为：

- Raw Documents Only；
- Raw Documents + Active Project Knowledge。

这是 deterministic proxy，不调用 LLM。`Gold Fact Hit`、`Answer Correctness`、`Faithfulness` 和 `Citation Support` 都基于冻结事实、来源元数据和 Provenance 完整性计算，不能冒充真人或模型语义评测。

当前结果：

| 方案 | Gold Fact Hit | Correctness | Faithfulness | Citation | 错误命中（撤销/旧版） | ACL | Provenance |
|---|---:|---:|---:|---:|---:|---:|---:|
| Raw Only | 0.125 | 0.500 | 1.000 | 1.000 | 0 | 0 | 1.000 |
| Raw + Active Knowledge | 0.625 | 1.000 | 1.000 | 1.000 | 0 | 0 | 1.000 |

结论：Active Project Knowledge 能补足 Raw 文档未覆盖的新结论，同时撤销、替代、Derived-only 和 ACL 边界没有错误穿透。它仍必须保持显式项目上下文开关，不能默认混入所有普通检索，也不能把该 proxy 写成“模型生成质量已证明”。

## 5. 最终架构决策

当前项目保留三条主线：

```text
普通科研问答：Hybrid + RRF + ACL + 选择性改写/扩展
复杂科研任务：Researcher → Analyst → Reviewer → 最多一次 Revision
可信知识沉淀：Evidence → Claim → Reviewer → 用户确认/项目发布 → 可撤销、可替代、可回查
```

停止新增 Agent、自动 Deep Router、第二套向量库、Step-back、Parent/Child、外部 Web Research 和基础设施扩张。后续只有在新冻结数据明确暴露失败时，才重新启动对应 POC；否则项目进入简历和面试准备阶段。

## 6. 复现实验

```bash
conda run -n agent-demo python -m tests.eval.run_秋招版检索评测
conda run -n agent-demo python -m tests.eval.run_秋招版技术分词消融
conda run -n agent-demo python -m tests.eval.知识演化生成评测
```

评测 JSON 和 Markdown 报告写入 `data/`，该目录按仓库策略忽略运行产物；冻结数据、执行脚本和契约测试纳入版本控制。
