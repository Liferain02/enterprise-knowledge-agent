# 配置、部署、运维与故障排查

本文给出从新环境安装到远程访问、模型代理、数据备份和常见故障定位的完整操作说明。端口转发的图解细节另见《启动与远程访问指南》。

## 1. 运行拓扑

当前推荐单机拓扑：

```text
个人电脑浏览器
  │ SSH -L 3000 / 8010
  ▼
计算服务器
  ├─ Vite 前端      0.0.0.0:3000
  ├─ FastAPI 后端   0.0.0.0:8010
  ├─ SQLite/Chroma  本地磁盘
  ├─ MCP 子进程     仅限 data/knowledge
  └─ 127.0.0.1:7897 ── SSH -R ──► 个人电脑代理（可选）
```

`ssh -L` 解决“个人电脑访问服务器服务”；`ssh -R` 解决“服务器借用个人电脑代理访问外部模型”。两者方向相反，不能互相替代。

## 2. 依赖准备

### 2.1 后端

项目启动脚本默认寻找 Conda 环境 `agent-demo`：

```bash
conda create -n agent-demo python=3.11
conda activate agent-demo
pip install -r requirements.txt
```

依赖包括 FastAPI、LangGraph/LangChain、Chroma、DashScope、BM25、jieba、文档加载器和可选 Mem0/MCP。服务器无互联网时，应提前准备 Conda 环境、wheel 缓存或通过批准的代理安装；不要让启动脚本每次联网安装依赖。

### 2.2 前端

```bash
npm --prefix frontend install
```

`scripts/start.sh` 直接使用 `frontend/node_modules/.bin/vite`，未安装依赖会明确退出。

## 3. 环境配置

先复制模板：

```bash
cp config/env.template config/.env
```

`config/.env` 含密钥，不能提交 Git。以下配置最重要。

### 3.1 LLM

```dotenv
LLM_PROVIDER=qwen
DASHSCOPE_API_KEY=真实密钥
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_MODEL=qwen3.5-flash
```

项目曾尝试 DeepSeek V4 Flash；若实际端点、模型权限或兼容性不可用，保持 Qwen 是当前稳定方案。模型切换必须用真实对话、流式和结构化输出验证，不能只验证一次 HTTP 200。

### 3.2 Embedding 与 Rerank

```dotenv
EMBEDDING_PROVIDER=qwen
EMBEDDING_MODEL=text-embedding-v2
RERANKER_ENABLED=true
RERANKER_PROVIDER=qwen
RERANKER_MODEL=qwen3-rerank
RERANKER_TOP_N=3
RERANKER_THRESHOLD=0.1
```

DeepSeek 类聊天模型通常不提供本项目需要的 embedding，因此对话模型与 embedding 要分开配置。Rerank 实际由 DashScope `TextReRank` 调用；模型名取决于账号可用模型和 `.env`，启动日志与真实检索比模板注释更可信。

更换 embedding 模型后必须重建向量库。只更换 rerank 模型不需要重新 embedding，但必须重新跑离线评测。

### 3.3 服务与认证

```dotenv
API_HOST=0.0.0.0
API_PORT=8010
AUTH_ENABLED=true
ADMIN_USERNAME=自定义管理员名
ADMIN_PASSWORD=强密码
JWT_SECRET_KEY=至少32字节的随机值
```

可生成 JWT secret：

```bash
openssl rand -hex 32
```

认证开启时，占位密码或过短 secret 会导致启动失败，这是安全保护而不是 bug。

### 3.4 RAG

常用参数：

| 参数 | 作用 | 调整依据 |
|---|---|---|
| `RETRIEVAL_TOP_K` | 最终候选数量 | Recall/Precision 和上下文预算 |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 基础字符分块 | 文档结构与漏召回案例 |
| `CHUNKING_STRATEGY` | 分块模式 | Markdown/PDF 类型 |
| `HYBRID_VECTOR_WEIGHT` | 向量权重 | 语义问题表现 |
| `HYBRID_BM25_WEIGHT` | 关键词权重 | 专名、编号、缩写表现 |
| `RERANKER_TOP_N` | 重排后保留数量 | 引用覆盖与生成成本 |
| `CRAG_*` | 评分阈值、并发、重试 | 标注集与延迟 |
| `QUERY_EXPAND_*` | 扩展策略与子查询上限 | 复杂查询评测 |

不要一次改多个权重和阈值，否则无法知道收益来自哪里。

### 3.5 记忆、限流和可选 Redis

```dotenv
SUMMARY_THRESHOLD=20
SUMMARY_KEEP_RECENT=6
MEM0_ENABLED=false
USE_SQLITE_CHECKPOINTER=true
RATE_LIMIT_ENABLED=true
```

Mem0 默认关闭也不影响核心问答。Redis 配置为空时评分缓存自动使用内存；单机部署无需为了“架构完整”强行增加 Redis。

## 4. 无网络服务器与代理

假设个人电脑代理监听 `127.0.0.1:7897`，从个人电脑建立 SSH 反向转发：

```bash
ssh -N -T \
  -R 7897:127.0.0.1:7897 \
  用户名@cpui01
```

服务器 `config/.env`：

```dotenv
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
```

项目 `main.py` 在模型客户端初始化前设置代理环境变量，并重置 LLM 缓存。如果只在 shell 中临时执行 `set_proxy`，要确认启动脚本继承了环境；写入 `.env` 更稳定。

验证顺序：

```bash
ss -ltn | grep 7897
curl -x http://127.0.0.1:7897 -I https://dashscope.aliyuncs.com
```

端口监听但请求失败时，检查个人电脑代理是否允许来自 SSH 的连接、SSH 会话是否仍存活以及模型域名是否被代理规则拦截。

## 5. 一键启动和停止

```bash
./scripts/start.sh
```

脚本执行以下保护：

- 固定使用不冲突的 3000/8010；
- 拒绝覆盖其他进程占用的端口；
- 检查 `config/.env`、Conda 环境和前端依赖；
- 后端就绪后才启动前端；
- 使用 PID 文件管理本项目进程；
- 任一阶段失败时清理本次已启动进程；
- 日志保存到 `.run/后端.log` 和 `.run/前端.log`。

停止：

```bash
./scripts/stop.sh
```

停止脚本会验证 PID 对应命令属于当前项目，避免误杀同机其他用户或其他项目进程；10 秒未退出才强制结束。

## 6. 访问方式

### 6.1 服务器本机

```text
前端：http://127.0.0.1:3000
接口文档：http://127.0.0.1:8010/docs
健康检查：http://127.0.0.1:8010/health
```

### 6.2 从个人电脑访问

在个人电脑另开终端：

```bash
ssh -N -T -o ExitOnForwardFailure=yes \
  -L 3000:127.0.0.1:3000 \
  -L 8010:127.0.0.1:8010 \
  用户名@cpui01
```

然后在个人电脑浏览器打开 `http://127.0.0.1:3000`。

不要用 `ssh -R 3000:...` 来访问页面；`-R` 是把个人电脑端口提供给服务器。更完整排查见《启动与远程访问指南》。

## 7. 日常检查

### 7.1 进程与端口

```bash
cat .run/后端.pid .run/前端.pid
ss -ltnp | grep -E ':3000|:8010'
```

### 7.2 健康

```bash
curl --noproxy '*' http://127.0.0.1:8010/health
curl --noproxy '*' http://127.0.0.1:8010/health/ready
curl --noproxy '*' -I http://127.0.0.1:3000/
```

`/health` 中 Redis 不可用但总体 degraded，不一定意味着问答不可用；应区分核心与可选组件。

### 7.3 日志

```bash
tail -f .run/后端.log
tail -f .run/前端.log
tail -f logs/agent.log
```

`.run` 是当前启动实例的 stdout/stderr；`logs/agent.log` 是应用结构化日志。排障时记录请求时间、用户名、session ID 和错误阶段，不要把 API key/JWT 贴入工单。

## 8. 数据备份与恢复

需要备份的默认路径：

- `chroma_db/`；
- `data/users.db`；
- `data/research_workspace.db`；
- `data/ingestion_queue.db`；
- `data/document_versions.db`；
- `data/knowledge/`；
- `config/.env` 应在安全密钥系统中单独备份，不进入普通归档。

一致性最高的做法是先停止项目，再复制 SQLite 与 Chroma 目录。仅复制一个正在写入的 SQLite 主文件可能遗漏 WAL 内容。

恢复后依次验证：数据库能打开、Chroma count 正常、登录成功、知识搜索成功、项目数据可见、真实问答带来源。

## 10. 故障排查矩阵

### 10.1 浏览器打不开前端

1. 服务器执行 `curl http://127.0.0.1:3000`；
2. 检查 `.run/前端.log`；
3. 个人电脑确认 SSH 使用 `-L`；
4. 检查个人电脑 3000 是否已被占用；
5. 浏览器必须打开个人电脑的 `127.0.0.1:3000`。

### 10.2 前端能开但接口失败

1. 检查 `8010/health/ready`；
2. 检查 Vite proxy 配置与 SSH 是否同时转发 8010；
3. 浏览器 Network 查看状态码；
4. 401 检查 token，403 检查角色，429 检查限流，500 查后端日志。

### 10.3 启动脚本提示端口占用

项目刻意不抢占 5173、5174、8000，也不会杀掉占用 3000/8010 的未知进程。使用 `ss -ltnp` 定位归属，停止正确服务或明确修改前后端配置，不要盲目 `kill -9`。

### 10.4 模型超时或无法连接

检查顺序：SSH `-R` 会话、7897 监听、代理 curl、`.env` proxy、API key、模型名、后端日志。Embedding、Rerank、Chat 是三个不同调用，要分别验证。

### 10.5 Qwen Rerank 未生效

确认 `RERANKER_ENABLED=true`、provider 为 qwen、模型在账号可用、DashScope key 有效；查看搜索日志是否出现 rerank 调用。即使失败系统也会降级，所以“搜索有结果”不能证明 rerank 已接入。

### 10.6 上传一直 pending

检查后台 Worker 是否随 lifespan 启动、任务详情中的 retry/error、文件是否可读、embedding 网络和磁盘空间。服务重启后 stale recovery 应恢复异常 running 任务。

### 10.7 搜索无结果

先查知识库 count，再用 `/knowledge/search` 测明确关键词；核对当前角色 visibility；查看源文件是否成功产生 chunk；最后再调阈值。不要第一步就降低所有相关性门槛。

### 10.8 SSE 一直加载

查看 Network 中连接是否持续收数据、后端是否卡在 grader/LLM、用户是否达到限流、模型代理是否中断。客户端可点击停止；服务端异常应产生 error/done，而不是无期限悬挂。

### 10.9 登录失败

区分注册用户和配置管理员；检查认证安全校验是否阻止启动；确认服务器时间没有大幅偏移导致 JWT 过期；角色变更后重新调用 `/auth/me` 验证实时权限。

## 11. 生产化注意事项

当前形态适合内网单机或小团队。若要公网/多实例部署，优先补：

1. HTTPS 与明确 CORS 来源；
2. 反向代理的 SSE 超时和缓冲配置；
3. 密钥管理而不是普通 `.env`；
4. SQLite/Chroma 的备份恢复演练；
5. WebSocket 完整 JWT 认证，或关闭不用的入口；
6. 多实例前再评估 PostgreSQL、共享向量库和 Redis。

不要在没有并发与可靠性证据时先引入 Kubernetes、消息总线或分布式事务。
