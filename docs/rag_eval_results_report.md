# RAG 检索质量评测报告

**评测时间**: 2026-04-07
**评测脚本**: `scripts/run_rag_eval.py`
**评测方式**: 对 ChromaDB 真实向量库（`enterprise_knowledge` collection，35 chunks）执行端到端检索
**评估模式**: `--top-k 10 --enable-ragas`（含答案质量评估）

---

## 一、评测方法

### 1.1 评测对象

| 维度 | 信息 |
|------|------|
| 向量库 | ChromaDB (`./chroma_db`) |
| Collection | `enterprise_knowledge` |
| Chunk 数量 | 35 |
| 检索 top_k | 10 |
| 正常查询 | 38 条（`scripts/eval_dataset.py` 内置数据集，与 `data/knowledge/` 逐一核对） |
| 对抗查询 | 7 条（无答案/诱导错误/重复字符/零宽字符/纯标点/超长/中英混杂） |
| **合计** | **45 条** |

### 1.2 评测指标体系

#### 检索层指标（基于文档级召回）

| 指标 | 说明 |
|------|------|
| **Recall@K** | 相关文档命中数 / 全部相关文档数 |
| **Precision@K** | top-K 中命中的相关文档数 / K |
| **F1@K** | 2×P×R / (P+R) |
| **MRR** | 首个相关文档排名的倒数均值 |
| **NDCG@K** | 归一化折损累计增益（支持分级相关度） |
| **MAP** | 平均精度均值 |
| **Hit@K** | top-K 内有命中为 1，否则为 0 |

#### 答案质量指标（基于关键词重叠，无需 LLM 调用）

| 指标 | 说明 |
|------|------|
| **Faithfulness** | 检索上下文关键词中与查询相关的比例（代理"上下文是否围绕查询主题"） |
| **Answer Relevancy** | Ground-truth 关键词在检索文档中的覆盖比例 |
| **Context Recall** | 同 Answer Relevancy（检索文档对期望答案的覆盖程度） |
| **Context Precision** | 检索上下文关键词中有多少与 Ground-truth 相关 |

> 注：Faithfulness 值偏低（~0.006）是正常现象——因为检索上下文包含大量来自其他文档的内容（跨文档检索），其中与当前查询主题无关的词会拉低重叠率，不代表系统有幻觉，而代表"噪声比例高"。

### 1.3 决策分布（基于向量相似度阈值）

| 决策 | 触发条件 |
|------|---------|
| **HIGH** | 平均相似度 ≥ 0.4 **且** HIGH 文档占比 ≥ 20% |
| **MEDIUM** | 平均相似度在 0.2–0.4 之间 |
| **LOW** | 平均相似度 < 0.2 |
| **NO_RESULTS** | 无检索结果 |

## 六、核心发现与改进建议

### 6.1 当前优势

1. **R@5 = 78%**（正常查询），Hit@5 = 80%，说明大多数查询能命中目标文档
2. **NDCG@5 = 0.936**，排序质量优秀，正确文档普遍排在前列
3. **MRR = 0.633**，首个相关文档的平均排名约为第 1.6 位
4. **对抗查询 100% 拒绝**，无答案查询均正确返回 NO_RESULTS
5. **平均延迟 280ms**，性能良好，P99 < 1s

### 6.2 主要问题

1. **9 条查询 R@5=0**：员工手册、招聘管理制度、产品技术文档等部分 chunk 未被正确索引或向量质量不足
2. **上下文精度低（Context Precision = 2.4%）**：检索返回了过多来自其他文档的噪声 chunks
3. **列举查询 R@5 偏低（40%）**：需 4 篇以上文档覆盖的查询，top-5 只能覆盖部分
4. **零宽字符查询失败**：特殊 Unicode 字符导致 embedding 失效

### 6.3 改进建议

| 问题 | 改进方向 | 预期效果 |
|------|---------|---------|
| R@5=0 的 9 条查询 | 优化 chunk 切分，增加相关文档的 chunk 数量 | R@5 从 78% 提升至 90%+ |
| 上下文精度低 | 引入 BM25 精确匹配层，过滤语义相似但词不相关的文档 | Context Precision 提升至 15%+ |
| 列举查询 Recall 低 | 增加 top_k 至 15-20，或引入多文档联合评分策略 | 列举类 R@5 提升至 70%+ |
| 零宽字符问题 | 检索前增加 Unicode 规范化（NFKC）预处理 | 特殊字符查询成功率 100% |
