# 02 智能体协议与流式输出故障复盘

本文覆盖多 Agent 最容易出现的协议、状态、输出和循环问题。

## 02.1 两层路由导致架构失控

### 历史问题

Planner、Supervisor、动态 Worker 和 Send fan-out 同时存在，仓库看起来能力丰富，但请求路径难以确认。

### 具体损失

- Planner 与 Supervisor 可能选择不同 Agent。
- 多一次模型调用和延迟。
- trace 不知道最终决策来自哪层。
- 旧代码存在就被误写进文档。

### 收敛

以 `create_multi_agent_graph()` 为准，只保留 Planner 唯一路由；Normal 固定 Retrieval→Generation，Deep 固定三角色，所有分支统一 Finalizer。

### 验证

图结构测试断言不存在 Supervisor/parallel node 和无界边，文档明确列兼容代码。

## 02.2 ReAct 检索循环不稳定

### 现象

Knowledge Agent 有时不调用检索、有时重复调用、有时把 tool result 写入历史。

### 根因

知识检索顺序本来是确定的，却把控制权交给生成模型。

### 修复

拆成无 ReAct 的 `retrieval_agent_node` 与 `generation_agent_node`。只在 Operation 这种动态工具选择任务保留 ReAct。

### 收益

retrieval 可独立评测，调用次数更可控，中间 tool messages 不污染会话。

## 02.3 内部模型 token 污染 SSE

### 现象

用户界面可能出现 Planner JSON、Reviewer decision 或 Analyst Claims，随后才出现最终答案。

### 根因

`astream_events` 会递归上报图中所有 chat model stream。只判断 event type 无法区分业务角色。

### 修复

最终 Generation 调用添加 `user_visible_answer` tag，ChatService 只转发包含该 tag 的 model stream。内部阶段只通过 `thinking` 发友好进度。

### 架构意义

“用户可见输出”成为显式协议，而不是靠节点名称黑名单。未来新增 Agent 默认不会泄漏，除非主动加 tag。

## 02.4 子 Agent 历史污染摘要

### 现象

Operation/General ReAct 的 tool call、tool result 和内部 AIMessage 全部回写主 messages，摘要长度快速增长，Mem0 还可能把工具返回当长期偏好。

### 修复

子 Agent 不使用独立 checkpointer；内部 messages 只在本轮存在，返回主图时只写最终 AIMessage。摘要和 Mem0 进一步只选择 human/ai 可见消息。

## 02.5 Structured output 不等于稳定协议

### 现象

模型可能使用字段别名、enum 对象、空 source IDs、只填 draft answer，Pydantic 语法通过却语义不合格。

### 处理层次

```text
AliasChoices / validator：兼容 wire 形态
normalize：统一 claim type、IDs、coverage
deterministic reviewer checks：发现非法/空引用
final validation：删除仍不合法 Claims
```

### 原则

模型负责开放语义，程序负责枚举、引用存在性、上限和终止性。

## 02.6 Reviewer 错误 PASS

### 现象

Claim 引用 S99 或没有引用，但 Reviewer 仍返回 PASS。

### 修复

在 LLM Reviewer 输出后合并 `_deterministic_review_issues()`；一旦有 invalid source/citation gap，强制 decision 至少 REVISE。

### 为什么不只强化 Prompt

Prompt 不能提供概率 1 的遵守；source ID 集合检查是简单确定性逻辑，不应交给模型。

## 02.7 普通问题被强行“前提核验”

### 现象

比较或建议题的回答顶部出现“证据不足以确认前提”，虽然用户没有提出待判真的命题。

### 根因

Reviewer 把问题中的“判断/是否”或绝对词过度泛化为 premise。

### 修复

`_is_premise_task()` 只识别明确验证/核验/能否认为/强命题形式。非 premise 确定性归一为 not_applicable，清空 premise sources 和 false-premise items。

### 仍有问题

V2 premise accuracy 仍明显回退，说明规则修了展示污染，但真假判断质量没有达到产品门槛。

## 02.8 Reviewer 无限回环风险

### 风险

Reviewer 每次都能要求更多证据，会形成搜索—分析—审查循环，费用和延迟无上限。

### 控制

- targeted queries 最多 2。
- revision count 最多 1。
- revision 后不回 Reviewer。
- 最终用无模型校验收口。

这使图可以证明终止，而不是靠 Prompt 请求自律。

## 02.9 Checkpointer 跨事件循环

### 现象

FastAPI 中异步图偶发阻塞或 aiosqlite 报 loop 相关问题。

### 根因

AsyncSqliteSaver 在 import 阶段或另一个 event loop 创建，实际请求在 Uvicorn loop 使用。

### 修复

通过 `get_agent_graph_async()` 在当前服务器 loop 延迟创建并缓存；同步测试使用 MemorySaver。

### 教训

异步资源单例不仅看 Python 对象生命周期，还要看它绑定的 event loop。

## 02.10 前端 SSE 跨 chunk 残帧

### 当前实现

每次 reader.read() 后按 `\n` 拆行，对 JSON parse error 静默忽略。

### 风险

网络 chunk 可能从一个 JSON 中间切开；前半和后半都会 parse 失败，token 或 sources 事件丢失。

### 正确修复方向

维护字符串 buffer，以完整 SSE frame `\n\n` 为单位消费，半帧保留到下一次 read，并在 stream done 时 flush decoder。

### 测试

人为将一个 data frame 切成每种边界，断言解析结果完全一致。这个问题目前记录为已知不足，不能在文档里声称 SSE 已覆盖任意分片。

## 02.11 浏览器取消不停止后端

AbortController 会关闭客户端 fetch，但服务器可能继续执行 LLM，造成看不见的 token 成本。

完整修复需要检测 request disconnect、取消图 task，并确认 SDK 支持 cancellation。当前没有为非阻断体验问题引入复杂任务系统，但应在成本敏感场景优先处理。

## 02.12 Finalizer 重复消息

不同 Worker 有的已返回 AIMessage，有的只返回 final_answer。若 Finalizer无条件追加，历史会重复。

当前比较最后消息类型和内容，相同则只返回 final_answer，否则追加一次。这个小逻辑维护了所有分支统一消息契约。

## 02.13 STAR 表达

> 多 Agent 接入后，SSE 会把 Reviewer JSON 和最终答案一起推给用户。我追踪 LangGraph v2 事件发现所有嵌套模型共享同一事件类型，因此没有写节点黑名单，而是在唯一用户可见生成调用上加 tag，流式服务只允许该 tag。随后补了内部消息不进入摘要和 Mem0 的契约，解决的是输出边界而不只是 UI 文本。
