## 1. 质量模型

```text
入库完整性
  → Retrieval candidate quality
  → Rerank / CRAG selection
  → Evidence coverage
  → Claim formation
  → Review decisions
  → Final answer coverage and citations
  → Product latency / cost / usability
```

任何上游为空，下游的更强 LLM 都不能凭空补出内部证据。反过来，Retrieval Recall 高也不代表最终答案正确：Analyst 可能漏用，Reviewer 可能误删，Generation 可能遗漏或错解。

## 2. 四类数据身份

### 2.1 Development

实现者可以查看问题、gold、中间结果和失败。它用来诊断和修复，不能证明新数据泛化。

### 2.2 Historical Blind V1

18 条 V1 曾在实现冻结后运行，但其 H06/H07/H08/H16 等失败已被实现者查看。所以 V1 现在的身份是：

```text
Historical Blind Holdout V1
+
Regression after inspection
```

可以用来检查修复后是否破坏旧行为，但不能宣称新 blind gain。

### 2.3 Blind V2

26 条新数据在源码、配置、测试、知识库 snapshot 和 gate 冻结之后创建。已完成 B Normal / C Deep 一次性自动运行。候选甲/乙人工评分包已生成，映射保持密封。

### 2.4 Regression

Regression 回答“已知能力有没有被破坏”，不回答“新能力是否泛化”。一个 case 被用于诊断后，就应转为 regression，不能再当 blind。

## 4. Retrieval-only Development Benchmark

### 4.1 数据分布

| 类别 | 数量 |
|---|---:|
| exact named document | 6 |
| named entity alias | 5 |
| multi evidence | 5 |
| temporal/version | 5 |
| semantic query | 5 |
| 总计 | 26 |

### 4.2 记录字段

每个 case 分别运行 Normal query 和实际 Deep Researcher subqueries，记录：

- 原 query 和子问题；
- rewrite history；
- raw candidates 及分数；
- rerank 后 candidates；
- final documents 和 rank；
- Hit@K、Recall@K、MRR；
- expected document coverage；
- query count 和 latency；
- failure attribution。

### 4.3 指标

#### Hit@K

```text
Hit@K = 1，当 Top-K 中至少有一份 gold document；否则为 0
```

适合“是否至少找到一份关键证据”，但不能表示多证据是否齐全。

#### Recall@K

```text
Recall@K = |Top-K 命中 gold| / |gold documents|
```

适合多文档综合。一道需要四份材料的问题只找到一份，Hit=1 但 Recall=0.25。

#### MRR

```text
MRR = mean(1 / first_relevant_rank)
```

反映第一份相关文档出现得多早。它不关心第二、第三份 gold，因此与 Recall 同时报告。

### 4.4 BEFORE / AFTER

| 阶段 | 方案 | Hit@K | Recall@K | MRR | P50/P95 |
|---|---|---:|---:|---:|---:|
| BEFORE | Normal | 0.808 | 0.686 | 0.788 | 2.4/3.8s |
| BEFORE | Deep Researcher | 0.808 | 0.705 | 0.788 | 5.6/6.5s |
| AFTER | Normal | 0.808 | 0.686 | 0.788 | 2.5/4.9s |
| AFTER | Deep Researcher | 0.808 | 0.673 | 0.808 | 5.9/7.6s |

AFTER 并不是一个检索优化版，而是增加了更准确的候选日志和失败归因。LLM 分解有运行波动，所以 0.705 和 0.673 不应被宣传为算法回退或改善。

### 4.5 失败归因

```text
query_planning_failure
lexical/title_failure
semantic_retrieval_failure
rerank_failure
ACL_filtering
missing_document
unknown
```

H08/H16 是 `missing_document`。该发现直接否定了“为已入库命名论文加 Anchor”的原始假设。

### 6.1 数据分布

### 6.2 预声明 gate

在看到 V2 结果前已写入：

- 26×2 都必须成功；
- ACL violation=0；
- Deep premise 不得低于 Normal 超过 0.10；
- temporal 必须人工平均高 0.50/6 且胜 5/8；
- named multi 必须人工平均高 0.50/6 且胜 4/6；
- recommendation/research brief 只有人工分不低且至少一半胜才可宣称无退化；
- P50/P95、calls、tokens 必须完整报告。

|---|---:|---:|

| 关键点覆盖 | 0.865 | 0.913 |

### 6.4 按类别解读

- temporal：自动 key point 0.875 → 0.906，document recall 0.833 → 1.000，有正向信号，但人工答案优势尚未证明。
- named multi：key point 持平 0.958，document recall 0.833 → 1.000，证明更多 gold 进了检索，不等于答案一定更好。
- recommendation/research brief：key point 持平 0.833，recall 0.389 → 0.569，不能依此声称没有退化。
- premise：key point 提高，document recall 持平，但明确 premise accuracy 从 0.667 降到 0.167，是 safety gate 失败。

### 6.5 当前状态

```text
Implementation + automatic eval complete
Independent human review pending
```

这不是“评测没做完就草草收尾”，而是为了不让实现者同时做最终人工 Judge。在映射解盲前，不得宣布 V2 最终产品收益。

## 7. 自动答案指标的局限

### 7.1 关键点覆盖

检查预期主题或关键表达是否出现。它不保证这些表达在语义上正确，更不保证结论没有被否定词改变。

### 7.2 Citation Coverage

检查需要证据的句子是否带了 `[\u6587\u6863N]`。有引用只能证明形式存在，不保证引用真的支持该句。

### 7.3 Citation Support Proxy

用引用句和对应文档的词汇重叠估计 support。它是回归信号，不是 NLI、事实蕴含或专家正确率。

### 7.4 Final Validated-Claim Coverage Proxy

先确认答案引用了 Claim 绑定的文档，再用拉丁词和中文 bigram 覆盖估计 Claim 是否真的被写入。它比“引用了同一文档就算覆盖”更严格，但仍不是语义 Judge。

## 8. 为什么不用 LLM-as-a-Judge

1. 当前开发者、模型提供商和被评答案风格高度关联，Judge 可能有风格偏好。
2. 用同类 LLM 评价同类 LLM 答案可能放大共同偏差。
3. 这一轮需要验证真实产品价值，而不是用额外 API 生成更漂亮的一个分数。
4. 候选数只有 26×2，独立人工核验在成本上可行。

这不代表任何项目都不应该使用 LLM Judge。对大规模日常回归，可以在有人工校准、一致性分析和偏差监控的前提下使用。

## 9. 公平对照

### 9.1 不修 Normal

V2 迭代不改 Normal Planner、Query Expansion、Retrieval、Generation Prompt、回答长度和路由。如果为了让 Deep 相对分数更高而降低 Normal，A/B 就失去意义。

### 9.2 相同外部条件

- 同一主 LLM：Qwen `qwen3.5-flash`；
- 同一 Embedding：`text-embedding-v2`；
- 同一 Reranker：`gte-rerank-v2`；
- 同一 Chroma snapshot；
- 同一 ACL 用户语义；
- 同一时期的网络和服务配置。

### 9.3 成本不能被质量均值隐藏

每个方案都报告 P50、P95、logical calls、input/output tokens。Deep 即使质量更高，也只有在用户了解等待和成本时才可能值得。

## 11. 当前能与不能宣称的结论

### 能宣称

- 实现了固定、有界、显式 opt-in 的 Deep Research。
- 在固定 26 条 Blind V2 自动评测中，Deep 文档召回和引用覆盖高于 Normal。
- Deep 延迟约为 Normal 的四倍，调用约 3.9 倍。
- 固定 ACL 矩阵和污染测试中没有拒绝文档泄漏。
- H08/H16 是未入索引的 knowledge gap。
- 现有 benchmark 不支持实施 Named Evidence Anchor。

### 不能宣称

- Deep 全局优于 Normal。
- temporal conflict 优势已在 V2 人工评价中重复。
- recommendation/research brief 已证明无退化。
- premise 判断可靠。
- ACL=0 代表绝对安全。
- citation support proxy 是事实正确率。
- 小规模单机结果可以外推到大规模企业部署。

## 12. 如何回答“结果到底好不好”

可以回答：

> 结果是局部正向、全局不足以扩大产品。Deep 在文档召回、引用覆盖和冲突类自动指标上更好，但前提判断严重退化，延迟和 token 明显上升。所以当前的成功不是“证明 Multi-Agent 更强”，而是用一套可审计的评测证明了它的价值边界，并根据边界保持 Normal 默认。
