# 09 科研空间、反馈与扩展协议

这些模块让项目从问答 Demo 变成可管理的实验室工具，但它们不是核心 RAG 主线。本文件详细说明完成度和边界。

## 09.1 科研空间数据模型

独立数据库 `data/research_workspace.db` 有四张表：

```text
research_projects
research_project_members
research_experiments
research_tasks
```

外键开启，子表引用 project ID，并配置级联删除。

## 09.2 Project

关键字段：slug、title、summary、research direction、status、visibility、lead、created_by、timestamps。

状态限定为 planned/active/paused/completed；visibility 为 public/project/restricted。slug 由中英文、数字、横线和下划线构造，冲突时追加 `-2/-3`。

## 09.3 Member 与权限

创建项目时 creator 和 lead 自动加入成员集合；lead 的 member_role 为 lead，其余为 member。

访问条件是 admin/pi、public、creator、lead 或 member 任一满足。写权限不因 public 自动获得，必须是特权角色或项目内部成员。

## 09.4 Experiment

记录：

```text
hypothesis / environment / code_commit
dataset_version / metrics JSON
conclusion / next_steps / status
```

metrics 必须是键值对象，SQLite 中 JSON 序列化，响应时恢复 dict。它提供最小可复现上下文，但没有自动追踪 GPU、依赖、artifact 或远程运行，不是 MLflow 替代品。

## 09.5 Task

Task 有 assignee、due date、status、source。状态限定 open/in_progress/done，列表按未完成优先和更新时间排序。

更新状态前先查 task，再按其 project 执行写权限检查，不能只凭 task ID 修改。

## 09.6 组会行动项提取

逐行识别 Markdown checkbox 或 TODO/待办/行动项/后续动作，使用 `|` 分列，并解析负责人和 `YYYY-MM-DD` 日期。

不使用 LLM 的原因是格式有限、结果可预测、无需网络且成本为零。当前不会做自然语言共指、相对日期或重复任务合并；若真实纪要超出规则，再增加“LLM 建议 + 人工确认”。

## 09.7 概览统计

服务按当前用户可访问项目计算 projects、experiments、open tasks、members、active projects 和 by status。先权限过滤再聚合，避免通过统计数字侧信道泄漏受限项目存在。

## 09.8 样例初始化

`seed_lab_samples()` 幂等创建 Distributed NUMA 和 RDMA Benchmarking 两个项目及实验/待办。通过 slug、实验标题和任务标题检查是否已存在。

样例 metrics 标记“待补充实测值”，不会虚构性能数据。这是可信演示的重要细节。

## 09.9 反馈模型

```text
helpful
incorrect
missing_material
```

保存 username、session、question、answer、used agent、type、comment 和时间。统计可按用户或全局聚合。

## 09.10 Issue 生命周期

只有 incorrect/missing material 进入 issue 列表：

```text
open ↔ resolved
```

resolved 必须填写 resolution note，并记录 resolved_by/at；重新打开时清空解决字段。

普通用户只能看自己的问题，审阅角色可看全局并处理。

## 09.11 从反馈到回归

代码实现到“采集、统计、处理状态”；修正文档和把案例加入 regression 是人工治理流程。

没有自动持续学习是刻意边界：用户可能误报或恶意提交，自动写知识库/训练集会污染事实。

## 09.12 Vision

独立接口：

- `/api/v1/vision/understand`：图片+问题。
- `/api/v1/vision/describe`：主体、文字、表格、布局和类型描述。
- `/health`：enabled、model、格式和大小配置。

ChatService 收到图片时先理解成文本，再进入主图。失败回退原问题。因此 LangGraph 继续处理统一文本 state。

当前没有图片 embedding、图文联合召回、OCR benchmark 或版面结构索引，准确定位是“多模态前置理解”。

## 09.13 Operation Agent

使用 `create_react_agent`，工具来自 datetime、calculator、general 和 MCP。内部自动进行 tool call loop，整体超时 180 秒。

它适合动态操作，不参与知识事实检索。MCP 未初始化返回空工具，计算/时间仍可用；超时返回明确建议。

## 09.14 General Agent

SkillLoader 创建 ReAct Agent，工具只有内置 general search 和最近会话关键词搜索，超时 120 秒。

general search 对时间可本地回答，对天气明确不能实时获取；它不是联网搜索服务。

## 09.15 MCP 初始化

```text
load config/mcp_servers.json
→ resolve project-relative args
→ concurrent stdio connections with timeout
→ list tools
→ inputSchema → Pydantic model
→ StructuredTool
→ Operation Agent
```

兼容新旧 MCP Python SDK 的 stdio API，并管理 context enter/exit。

## 09.16 MCP 参数类型化

适配器为常见 filesystem tools 预定义详细 schema；未知工具从 inputSchema 推导 string/integer/number/boolean/array/object。调用前 Pydantic 校验，失败返回友好错误。

这减少模型传错参数，但不能替代 server 端权限检查。

## 09.17 MCP 文件安全边界

当前唯一 filesystem server 启动参数把根目录限定为：

```text
data/knowledge
```

Agent 不能因为工具参数写绝对路径就访问整个服务器。write_file 仍可能覆盖白名单内资料，因此只能路由给有明确操作意图的 Operation Agent，未来还可增加写操作人工确认。

## 09.18 A2A Agent Card

`/.well-known/agent.json` 声明服务名、URL、版本、streaming capability、skills、provider、Bearer auth 和 endpoints。agent ID 由固定名称/版本哈希生成。

它用于能力发现，不代表所有 metadata 特性当前启用；例如 Mem0 默认关闭，Card 的 features 应长期与实际配置同步。

## 09.19 A2A 简化消息

`/api/v1/a2a/send` 只提取 text parts，生成/复用 session ID，并以固定 `a2a_agent` 用户调用 `ChatService.achat()`。响应返回文本、agent 和 message ID。

task 查询只是将 task ID 映射为 session，状态直接返回 completed。没有独立任务状态机、取消、push notifications、streaming A2A 或技能选择。

## 09.20 A2A 安全边界

固定 a2a identity 不等于调用方身份委托。若对外开放，至少需要：

- 认证和调用方到本地用户映射；
- 权限/配额；
- 审计和重放防护；
- task 生命周期；
- 输入大小与内容限制。

因此面试表述应是“Agent Card + 基本互操作验证”，不能说完整生产 A2A。

## 09.21 辅助模块优先级

正确排序：

1. 入库、检索、ACL、回答和来源正确。
2. 反馈问题能被处理。
3. 科研项目和实验记录可持续使用。
4. Vision/MCP/A2A 在不影响主线时按真实需求扩展。

协议和功能数量不是项目质量指标。辅助模块的价值是形成产品闭环，而不是抢占核心优化资源。
