# 10 模型配置、缓存、代理与部署

本文解释 Qwen/DeepSeek 配置边界、三类模型为何分开、无网环境如何使用代理、Redis 如何降级，以及一键启停脚本如何避免误杀其他项目。

## 10.1 配置加载

`Settings` 使用 Pydantic Settings，从 `config/.env` 读取，大小写不敏感，多余变量忽略。`get_settings()` 延迟创建单例，并确保 Chroma 和知识目录存在。

真实凭据只放 `.env`，模板只保留占位值。文档、日志、评测结果都不能写 key、密码和 JWT secret。

## 10.2 三类模型独立配置

```text
LLM_PROVIDER / Chat model
EMBEDDING_PROVIDER / Embedding model
RERANKER_PROVIDER / Rerank model
```

当前主链：

```text
Chat       qwen3.5-flash
Embedding  text-embedding-v2
Rerank     gte-rerank-v2
```

DeepSeek 等 OpenAI-compatible 服务可能只提供 Chat，不提供 Embedding/Rerank，因此切 Chat provider 时后二者仍保持 Qwen。

## 10.3 Qwen 与 DeepSeek 备用配置

`get_llm()` 支持 `qwen` 和通用 `openai` provider。DeepSeek base URL/model 可放在 OpenAI 备用字段中；当前实际 `LLM_PROVIDER=qwen`，因此运行主模型是 Qwen。

项目没有实现请求失败后自动从 DeepSeek 切 Qwen 的 runtime failover。当前策略是配置层选择：DeepSeek 不稳定时把 provider 保持/切回 Qwen，重新启动并验证。

不做自动 failover 的原因：

- 两个模型输出和 structured output 行为不同；
- 同一次正式评测不能中途换模型；
- 自动切换会掩盖故障和成本；
- Embedding/Rerank 本来就独立。

如果未来需要 HA，应把模型 fallback、重试预算、幂等和监控作为独立方案，而不是在异常捕获里静默换模型。

## 10.4 LLM 实例缓存

`get_llm()` 用 `lru_cache(maxsize=4)`，缓存键来自 model/temperature/max tokens/provider 参数。相同配置复用 ChatOpenAI client，避免每节点重复初始化。

配置修改后要调用 `reset_llm()` 或重启；否则进程内缓存仍使用旧实例。这也是部署修改模型后必须重启的原因。

## 10.5 关闭 Qwen thinking

qwen3.5-flash 默认可能开启思考，长 RAG Prompt 在 max tokens 内只产生 reasoning content 而没有最终正文。产品问答创建 client 时传：

```python
extra_body={"enable_thinking": False}
```

内部思考并不自动提高可用性，反而会增加延迟并破坏流式正文协议。Deep 的结构化阶段也需要可解析输出而不是 reasoning-only。

## 10.6 Embedding 实现

Embedding adapter 根据 provider 创建 Qwen 或 OpenAI Embeddings，负责 query/doc 向量。它与 chunk token estimator 中的模型名称不是同一概念：后者只帮助估算 token，前者真正调用向量 API。

更换 Embedding 会改变向量空间，必须重建 Chroma 并重跑 retrieval baseline，不能对旧向量直接换 query encoder。

## 10.7 Reranker 实现

Qwen Reranker 通过 DashScope `TextReRank`，不是 ChatOpenAI。provider manager 也保留 FlashRank/BGE 等适配，但当前配置是 Qwen。

全局 manager 延迟初始化；配置变更后同样应重启或重置单例。失败退回原顺序，核心问答仍可用。

## 10.8 代理配置

Settings 有 `HTTP_PROXY/HTTPS_PROXY` 对应字段。启动环境中的小写/大写变量会被 HTTPX 使用；Qwen Rerank 还设置 DashScope SDK 专用代理变量。

远程服务器通过 SSH reverse tunnel 使用本地代理时，典型场景是：

```text
开发机代理 127.0.0.1:7897
ssh -R 7897:127.0.0.1:7897 user@server
服务器 HTTP_PROXY=http://127.0.0.1:7897
```

网页访问则相反，使用 `ssh -L 3000... -L 8010...`。代理回传和网页端口转发不能混淆。

## 10.9 分依赖健康检查

排查代理时分别验证：

1. 代理端口可连接。
2. Chat 最小调用。
3. Embedding 单文本调用。
4. TextReRank 两文档调用。
5. Vision（若启用）。

不能用 Chat 成功推断所有 DashScope 服务成功。

## 10.10 Redis 配置

`REDIS_HOST=disabled` 时直接使用内存缓存。连接配置包含 2–3 秒超时，ping 失败记录 warning 并降级。

Redis 主要用于：

- CRAG grade cache；
- rate limit 计数等辅助能力。

入库任务不依赖 Redis，核心 RAG 也不因 Redis 缺失拒绝启动。

## 10.11 缓存 key 与 ACL

Grade cache 只缓存 query-doc 相关性分，不缓存“用户是否可访问”；调用它之前仍必须完成 ACL。
最终答案、检索结果和 Query Cache 已删除，不存在跨用户复用这三类业务结果的路径。

## 10.12 内存缓存降级

通用缓存内存层最多约 200 项，维护 TTL 和 LRU 访问顺序。Redis 断开时可用，但：

- 多进程不共享；
- 重启丢失；
- 不适合精确全局 rate limit；
- 命中率统计只代表当前进程。

这正符合降级定位，不应冒充 Redis 等价替代。

## 10.13 为什么删除 Query Cache

旧 Query Cache 没有接入主请求链，而且答案缓存若缺少用户 ACL、文档版本和时间有效性键，
存在跨权限复用旧来源的风险。当前数据规模也没有缓存最终答案的必要，因此直接删除，
不引入 Redis，也不维护一套无法由评测证明价值的失效协议。

## 10.14 Rate limiting

Settings 定义全局、匿名、chat 和 ingest 每分钟上限。限流的目标是防止滥用和外部 API 成本爆炸，不是吞吐性能优化。

内存计数在多实例下不精确；若部署多进程，需要 Redis 或网关统一限流。429 应带可理解提示，并纳入真实运行指标。

## 10.15 一键启动脚本

`scripts/start.sh`：

1. 严格 shell 模式 `set -Eeuo pipefail`。
2. 创建 `.run` 日志/PID 目录。
3. 检查脚本记录的旧进程。
4. 检查 8010/3000 是否被其他程序占用。
5. 检查 `config/.env`。
6. 使用当前或 `conda run -n agent-demo` 找后端 Python。
7. 检查 Vite binary 已安装。
8. nohup 启动后端，等待 `/health/ready` 最多 45 秒。
9. 启动前端并等待首页最多 20 秒。
10. 任一失败打印最近日志并清理本次启动的进程。

它不会因为某端口已有服务就强杀进程，避免影响同服务器的其他项目。

## 10.16 一键停止脚本

`stop.sh` 只读取 `.run/前端.pid` 和 `后端.pid`。停止前检查：

- PID 是数字且存活；
- command line 包含当前项目绝对路径。

先发送 TERM，等待最多 10 秒，再 KILL；过期 PID 只清理文件。日志保留用于排错。

这是比 `pkill -f python` 安全得多的项目级停止策略。

## 10.17 端口与绑定

```text
Frontend 0.0.0.0:3000
Backend  0.0.0.0:8010
```

选择 3000/8010 是为避开另一个项目的 5173/5174/8000。服务器本机先用 127.0.0.1 检查，再配置 `ssh -L` 从个人电脑访问。

绑定 0.0.0.0 便于内网访问，也扩大暴露面；防火墙、认证和网络策略仍需要部署方负责。

## 10.18 Readiness 与 liveness

启动脚本等待 `/health/ready`，确保应用初始化完成。普通 `/health` 可用于前端连通性。

外部模型短时故障不应让进程 liveness 失败并被无限重启；更合理的是 readiness/details 报告依赖状态，核心进程仍存活并提供降级提示。

## 10.19 安全启动校验

Auth 开启时：

- 管理员密码不能是公开占位值。
- JWT secret 至少 32 字符且不能是常见占位。

配置问题在启动阶段抛错，而不是服务上线后才发现。`.env` 权限和 secret 轮换仍是运维职责。

## 10.20 部署边界

当前是一键启动的单机原型，不包含：

- systemd/Kubernetes 高可用；
- 多实例共享 session/checkpoint；
- TLS 终止与正式域名；
- 集中日志、指标和告警；
- PostgreSQL/Redis 强依赖；
- 自动模型 failover。

面试可以讲清演进路线，但不能说已经完成生产集群部署。
