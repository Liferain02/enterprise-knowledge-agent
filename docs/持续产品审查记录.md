## 第 6 轮：纠正产品优先级并修复可信回答主链路

日期：2026-08-09

### 定位与优先级纠正

本项目的核心不是账号系统或通用 Agent 平台，而是实验室内部科研知识闭环：

1. 资料能稳定入库并持续更新；
2. 成员能检索到正确资料；
3. 回答只展示最终结论，并携带可核查来源；
4. 不准确或缺资料的回答能进入维护闭环；
5. 项目、实验和组会记录作为第二条协作主线。

认证、MCP、多 Agent 编排和部署能力只作为支撑层。后续审查不再连续扩展认证功能；除非存在正在阻断核心流程、造成越权或数据丢失的明确问题，否则优先资源投入上述主链路。

## 第 11 轮：收敛多 Agent 主链并建立架构评测

日期：2026-08-09

### 本轮 Goal

在不新增 Agent、框架、Redis 或其他基础设施的前提下，将请求链路收敛为“单一路由器 + ACL 感知的确定性知识 RAG + 按需工具 Agent + 统一终态”，修复复杂查询不可执行、状态重复、记忆阻塞和评测对象错误，并用真实 SSE 请求验证。

### 架构实现

- 本地 LangGraph 最小复现确认：普通节点返回 `List[Send]` 会触发 `InvalidUpdateError`。生产图删除 Supervisor、Execute Plan 和 Send Worker；对比、列举、多文档问题统一进入带 Query Expansion 的 ACL RAG 主链。
- Planner 成为唯一入口路由器；规则可确定时不调用路由 LLM，无法识别时安全降级到知识检索。
- Knowledge、Operation、General 全部进入统一 Finalizer；子 ReAct Agent 不再持有私有 checkpointer，也不把工具消息写回主会话。
- 摘要只统计用户可见的 user/assistant 消息，工具消息不再提前触发或污染摘要。
- Mem0 每轮从两次检索、两次写入收敛为各一次；写入移出 LangGraph 和 SSE 关键路径，底层同步调用使用线程执行，回答结束不再等待记忆提取或遥测网络。
- 首条消息标题改为确定性截取，移除一次与核心能力无关的同步 LLM 调用。
- SSE 不再暴露 `maybe_summarize`、`route_from_planner` 等内部节点名，只输出“正在检索资料”和“正在组织回答”等产品状态。
- 生成上下文和来源卡上限统一为 5，避免答案引用“文档 4/5”但页面只能看到 3 张来源卡。

### 评测修正

- 评测集替换为 20 条与当前实验室资料逐条对应的问题，覆盖制度、组会、新人、RDMA、集群、论文、会议纪要、跨文档对比和无答案。
- 检索评测改为调用线上相同的 ACL、Hybrid、Qwen Rerank 和 CRAG 链路，不再直接绕过到 Chroma。
- 原“RAGAS/Faithfulness”实际只计算上下文关键词重叠，现改名为上下文覆盖指标，不再冒充最终答案质量。
- 文档级指标按来源去重，修复同一文档多个 chunk 让 NDCG/MAP 大于 1；无答案查询独立计算正确拒答率。
- 增加纯标点与超长单字符输入的轻量有效性检查，quick eval 的无答案正确拒答率从 50% 提升到 100%。

### 验证证据

- 新增架构契约覆盖复杂查询路由、单一路由图、统一终态、摘要、Mem0 单次读写和非阻塞、指标去重、无语义拒答与确定性标题。
