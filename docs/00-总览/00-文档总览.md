这是项目文档的唯一入口。项目统一称为“实验室科研助手”，面向实验室成员管理资料、检索证据、记录实验，并在明确边界内完成复杂科研问答。文档按面试准备和实际维护顺序组织，先讲项目为什么存在，再讲代码如何运行，最后讲评测证明了什么、没有证明什么。

如果不熟悉英文缩写，先看[术语速查与面试表达](03-术语速查与面试表达.md)，再阅读后面的架构和代码文档。

## 1. 先记住项目重点

项目的核心不是登录页、智能体数量或堆叠基础设施，而是三条主线：

```text
实验室资料
  → 解析、切块、向量化
  → 向量检索 + BM25 关键词检索 + RRF 融合 + 权限过滤
  → 带来源回答

复杂科研问题（用户主动选择）
  → Researcher 检索证据
  → Analyst 整理声明
  → Reviewer 审核声明
  → 最多一次修订
  → 最终回答

可信知识沉淀
  → Evidence 证据
  → Claim 声明
  → 审核、用户确认或项目发布
  → 可追溯、可撤销、可替代、按权限回查
```

普通模式是默认路径，深度研究模式必须由用户显式选择。存储升级不改变这一产品边界；数据库选型与新增语料的质量验证见本次部署文档。

## 3. 当前实现状态

- 后端：Python、FastAPI、LangGraph，部署使用 MySQL、Qdrant、Redis，保留 SQLite / Chroma 兼容路径；前端：Vue 3、TypeScript、Vite。
- 检索：向量 + BM25，经 RRF 融合；Qwen 重排保留为可配置能力，但当前快照没有证明它优于 RRF。
- 权限：存储层过滤加 Python 二次校验，ACL violation 在冻结矩阵中为 0。
- 入库：批量同步采用 SHA-256 身份与先写新块、验证后删旧块；在线路径已统一字符分块、验证新块后发布版本，并通过元数据事务和稳定版本 ID 支持重试；仍非 MySQL/Qdrant 跨库原子发布，详见 Harness 实现报告。
- 工具：operation 按任务装载计算、时间、科研分析和论文写作能力，并限制模型次数、工具次数、时限与输入输出大小；文件操作不在该节点白名单内。
- 记忆：Mem0 默认开启，初始化或保存失败时降级；它是辅助上下文，不是自动学习系统。
- 评测：秋招版检索集 28 条、知识演化 8 个场景；`390 passed` 是此前一次依赖环境下的历史快照，不代表本次运行结果。

## 4. 证据边界

| 证据 | 可以怎么说 | 不可以怎么说 |
|---|---|---|
| 代码 | 实现了混合检索、ACL 和有界深度研究模式图 | 因此绝不会出错或泄漏 |
| 自动测试 | 固定矩阵中 violation=0 | 已经达到绝对安全 |
| 自动评测 | 当前数据和模型快照上召回有变化 | 最终答案质量永久提升 |
| 模拟评分 | 用于定位失败和校准规则 | 冒充独立真人盲评 |

当前最重要的负结果是：重排模型、技术分词和更多智能体没有稳定收益；深度研究模式的前提判断指标低于普通模式，因而不能宣布深度研究模式全局更好。没有新的失败证据前，项目进入面试材料和回归维护阶段。面试材料新增的智能体通用题，来自公开技术资料和常见能力要求的归纳，不是任何公司的真实题库。

## 5. 文档维护规则

1. 所有项目说明、报告和任务书放在 `docs/`，文件名使用中文和序号。
2. `README.md` 只保留给使用者的简介、启动命令和本入口链接。
3. `src/agent/skills/*/Skill.md` 是运行时提示文件，属于代码约定，不移动、不改名。
4. `data/knowledge/` 下的 Markdown 是待入库科研资料，`data/` 下的评测输出是运行产物，均不属于项目说明文档。
5. 历史报告保留原始结论，但必须注明日期、数据集和“历史证据”状态。
6. 架构变化要同步更新本入口、架构文档、代码导航和评测说明。
7. 不记录密钥、口令、真实用户资料；不把旧路线或“下一步计划”写成当前待办。
