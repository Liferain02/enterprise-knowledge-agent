# 术语速查与面试表达

> 这不是需要背诵的英文单词表。先理解中文含义，再记住面试中常见的英文缩写。

## 1. 阅读原则

项目文档遵循三条规则：

1. 第一次出现术语时，先写中文含义，再附英文或缩写。
2. 后续优先使用中文；只有代码名称、配置项、模型名和指标公式保留英文。
3. 面试回答先讲“解决什么问题”，再讲术语，不用连续堆砌名词。

例如，不要一上来就说：

> ACL-aware 混合检索 RAG 经过 RRF、重排和回答生成。

更容易理解的表达是：

> 系统先按用户权限过滤资料，再同时使用关键词检索和向量检索找候选，通过排名融合和重排选出证据，最后生成带引用的回答。这条链路通常称为带访问控制的混合检索增强生成。

## 2. 架构术语

| 常见写法 | 中文理解 | 本项目中的含义 | 面试一句话 |
|---|---|---|---|
| Agent | 智能体 | 能读取状态并执行检索、分析或工具调用的节点 | 智能体不是越多越好，关键是职责和停止条件 |
| Workflow | 固定工作流 | 步骤和分支由代码预先定义 | 普通模式采用固定工作流，便于测试和控制成本 |
| Multi-Agent | 多智能体 | 多个有限职责节点协作 | 深度研究模式只有资料研究员、分析员、审核员三个角色 |
| Planner | 路由规划器 | 判断请求进入知识、工具、通用或显式深度研究分支 | 当前规划器主要做确定性路由，不生成自由执行计划 |
| 资料研究员 | 资料研究员 | 拆分问题并收集证据 | 只负责找证据，不负责直接下结论 |
| 分析员 | 分析员 | 将证据整理成声明 | 每条声明必须绑定证据编号 |
| 审核员 | 审核员 | 检查声明、引用、冲突和错误前提 | 最多触发一次修订，避免无限循环 |
| 状态 | 状态 | 节点之间共享的结构化数据 | 状态字段比智能体自由聊天更容易测试 |
| Checkpoint | 状态检查点 | 保存会话图的可恢复状态 | 流式输出结束后以检查点中的最终状态为准 |
| Trace | 执行轨迹 | 记录每个阶段的输入摘要、耗时和决策 | 用轨迹判断错误发生在检索、分析还是生成 |

## 3. 检索与生成术语

| 常见写法 | 中文理解 | 本项目中的含义 | 面试一句话 |
|---|---|---|---|
| RAG | 检索增强生成 | 先从资料库找证据，再让模型回答 | 证据不能保证绝对正确，但能降低无依据生成并支持追溯 |
| Retrieval | 检索 | 从关键词索引和向量库取回候选文档 | 检索失败和最终回答失败要分开评测 |
| BM25 | 关键词相关性算法 | 擅长论文名、缩写、命令和精确术语 | 它补足纯向量检索对精确词不稳定的问题 |
| Embedding | 向量表示 | 把问题和文档转换为可比较的数值向量 | 对话模型和向量模型必须分开配置 |
| Dense Retrieval | 纯向量检索 | 只按向量相似度召回 | 擅长同义表达，但可能漏掉精确技术词 |
| 混合检索 Retrieval | 混合检索 | 同时使用关键词检索和向量检索 | 两路互补，当前使用固定权重 |
| RRF | 倒数排名融合 | 根据不同检索结果中的名次合并候选 | 不直接相加不同量纲的原始分数 |
| Rerank | 重排 | 对已召回的少量候选重新排序 | 能改善排序，但不能找回候选集中不存在的文档 |
| 查询 Expansion | 查询扩展 | 将一个问题改写或有限拆分后再检索 | 普通模式用它处理复杂问题，不自动进入多智能体模式 |
| CRAG | 纠错检索增强生成 | 对候选评分，必要时改写后重试 | 当前消融没有稳定收益，所以默认关闭 |
| Chunk | 文档片段 | 文档切分后进入向量库的基本单位 | 太小会丢上下文，太大容易稀释相关信息 |
| Generation | 回答生成 | 根据已经筛选的证据生成最终文本 | 普通模式和深度研究模式复用同一生成规则 |
| Citation | 引用 | 回答中的文档编号和来源信息 | 有引用不等于引用一定支持该句，需要单独校验 |

## 4. 权限、记忆和工具术语

| 常见写法 | 中文理解 | 本项目中的含义 | 面试一句话 |
|---|---|---|---|
| ACL | 访问控制规则 | 根据公开范围、项目、部门和角色过滤资料 | 必须在重排和模型调用前过滤，不能生成后再删除 |
| JWT | 登录身份令牌 | 证明请求是谁 | 每次请求仍从数据库刷新角色，避免旧令牌保留旧权限 |
| Mem0 | 长期记忆组件 | 保存有限的用户偏好和对话线索 | 它是辅助上下文，不是自动学习，也不能替代资料证据 |
| Summary | 对话摘要 | 压缩较早的用户可见消息 | 用于控制上下文长度，不等于长期记忆 |
| 工具调用 | 工具调用 | 模型输出结构化调用意图，由程序决定是否执行 | 参数格式正确不代表有权限，仍需校验范围和错误处理 |
| MCP | 模型上下文协议 | 本项目用于接入受限文件工具 | 文件工具只允许访问 `data/knowledge` |
| SSE | 服务端事件流 | 后端持续向浏览器推送进度和回答片段 | 适合单向流式问答，比双向通信更简单 |

## 5. 深度研究数据术语

| 常见写法 | 中文理解 | 本项目中的含义 | 面试一句话 |
|---|---|---|---|
| 证据 | 证据 | 带来源编号和权限校验结果的原始材料 | 没有证据就不应形成确定性声明 |
| EvidencePackage | 证据包 | 资料研究员交给分析员的结构化结果 | 包含证据、缺口、冲突和子问题 |
| 声明 | 声明 | 分析员根据证据形成的事实、比较、推断或建议 | 每条声明必须绑定真实存在的证据编号 |
| ReviewReport | 审核报告 | 审核员对声明支持关系的检查结果 | 结构合法不等于内容正确，之后还有确定性校验 |
| 前提判断 | 前提判断 | 判断用户问题中的前提是否成立 | 深度研究模式该指标明显退化，因此不能默认开启 |
| Revision | 修订 | 根据审核结果重写分析或补充有限证据 | 最多一次，确保成本和运行时间有上限 |

## 6. 评测术语

| 常见写法 | 中文理解 | 回答时要强调什么 |
|---|---|---|
| 基准测试 | 基准测试集 | 固定问题、目标文档、配置和统计口径后再比较方案 |
| Development Set | 开发集 | 可以反复查看和调试，不能用来证明泛化能力 |
| Blind Set | 盲测集 | 冻结代码后才创建或一次性运行，减少针对题目调参 |
| Regression Set | 回归测试集 | 已经查看过，只用于防止旧问题重新出现 |
| Gold | 标准目标 | 预先标注的目标文档、事实或答案要点 |
| Proxy Metric | 代理指标 | 容易自动计算，但不能直接等同于真人质量判断 |
| Hit@K | 前 K 条至少命中一次 | 只关心有没有命中，不关心命中了多少目标 |
| 召回率@K | 前 K 条目标覆盖率 | 目标文档较多时比命中率更有信息 |
| MRR | 首个正确结果的倒数排名均值 | 越早出现第一条正确结果越好 |
| NDCG | 考虑等级和位置的排序质量 | 同时关注多条结果的重要程度和排序位置 |
| P50/P95 | 中位数/长尾延迟 | 平均延迟会掩盖少数非常慢的请求 |
| LLM-as-a-评分器 | 用大模型评分 | 可用于趋势和失败分析，但必须警惕文风偏好和同源偏差 |
| Ablation | 消融实验 | 一次只移除或改变一个因素，确认收益来自哪里 |
| 安全门槛 | 安全门槛 | 即使平均指标提高，关键安全指标退化也不能上线 |

## 7. 面试回答模板

遇到陌生术语或追问时，按下面顺序回答：

1. **中文定义：**它解决什么问题。
2. **项目实现：**本项目在哪个模块使用。
3. **数据证据：**评测结果支持什么结论。
4. **边界取舍：**它没有解决什么，为什么没有继续扩张。

例如面试官问“为什么使用多智能体”时，可以回答：

> 多智能体适合职责天然可拆、需要独立审核的任务。本项目只在用户明确选择深度研究时，将任务拆成资料收集、声明整理和证据审核三个角色；普通问题仍走两阶段检索与生成。冻结评测显示深度模式能找齐更多文档，但前提判断和延迟明显变差，所以我没有自动路由，也没有增加第四个角色。

这比只回答“用了 LangGraph 和三个智能体”更容易让面试官理解你的工程判断。
