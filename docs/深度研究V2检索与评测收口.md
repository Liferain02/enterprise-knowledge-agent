# 深度研究 V2 检索与评测收口

本文记录 2026-08-13 的 Deep Research V2 收口。它回答的是“当前价值边界是否可信”，不是继续证明多智能体全局优于单智能体。

## 1. 结论先行

本轮得到五个明确结论：

1. H08/H16 的 Nu、Quicksand、Argo、AIFM 漏召回首先属于 `missing_document`：PDF 在工作目录中，但不在冻结 Chroma snapshot；不是已入库文档被向量检索漏掉。
2. 26 条 retrieval-only Development Benchmark 没有支持 Named Evidence Anchor。Deep Researcher 对命名组与 Normal 持平，整体 Recall AFTER 反而略低，因此没有改 Retrieval。
3. Reviewer 的 premise 任务边界已收紧：普通比较、总结、建议强制 `not_applicable`；明确验证任务仍使用 supported / unsupported / insufficient。
4. ACL 完整角色矩阵和 Deep 全阶段污染测试均通过，ACL violation = 0。
5. Blind V2 自动指标完成，但 Deep premise accuracy 只有 0.167，低于 Normal 0.667；独立人工评分尚未完成，因此不得给出 V2 最终生产收益结论。

产品身份保持不变：

```text
normal = default
deep = explicit opt-in
automatic routing = false
```

## 2. 本轮没有做什么

没有增加第四 Agent、Supervisor、动态 Worker、Reviewer 循环、共享 Blackboard、长期团队记忆、Redis、Kafka、GraphRAG、知识图谱、新向量库、新 Embedding、新 Reranker、新主 LLM、MCP 扩展或 LLM Judge。

Normal 的 Planner、Query Expansion、Retrieval、Generation Prompt、回答长度和路由规则均未修改。唯一生产行为新增是前端将既有 API 参数暴露为显式、单请求级模式选择。

## 3. Retrieval Failure Analysis

### 3.1 为什么先建 retrieval-only benchmark

最终答案失败可能来自检索、分析、审查或生成。只看答案无法证明是哪一层出了问题。因此新增：

- `tests/eval/deep_research_retrieval_dev_dataset.py`；
- `tests/eval/run_deep_research_retrieval_eval.py`。

数据集有 26 条，覆盖：

| 类别 | 数量 | 目的 |
|---|---:|---|
| exact_named_document | 6 | 标题或项目/论文名明确出现 |
| named_entity_alias | 5 | 简称、英文名、中文描述、标点变体 |
| multi_evidence | 5 | 同时找到 2～4 份材料 |
| temporal_version | 5 | 计划、纪要、规范和阶段材料 |
| semantic_query | 5 | 不出现标题，只依赖语义 |

每个变体记录 query、subquestions、rewrite history、raw candidates、rerank 后候选、最终文档、rank、Hit@K、Recall@K、MRR、expected coverage、查询数和延迟。

失败类型统一为：

```text
query_planning_failure
lexical/title_failure
semantic_retrieval_failure
rerank_failure
ACL_filtering
missing_document
unknown
```

### 3.2 H08/H16 的真实原因

冻结知识库为 40 chunks / 18 documents。目录中的四篇 PDF 没有出现在 Chroma 的 title/source 集合中：

- Nu；
- Quicksand；
- Argo；
- AIFM。

因此当前系统根本无法从检索索引返回这些内容。文件“存在于磁盘”和“已经入知识库”是两个不同状态。为遵守 Blind V1 冻结规则，本轮没有重新入库、没有改标题、没有增加 gold、没有把目标文档强塞进 EvidencePackage。

### 3.3 Retrieval BEFORE / AFTER

| 阶段 | 方案 | Hit@K | Recall@K | MRR | P50/P95 |
|---|---|---:|---:|---:|---:|
| BEFORE | Normal | 0.808 | 0.686 | 0.788 | 2.4s / 3.8s |
| BEFORE | Deep Researcher | 0.808 | 0.705 | 0.788 | 5.6s / 6.5s |
| AFTER | Normal | 0.808 | 0.686 | 0.788 | 2.5s / 4.9s |
| AFTER | Deep Researcher | 0.808 | 0.673 | 0.808 | 5.9s / 7.6s |

AFTER 只是增加更强的候选阶段归因，检索实现没有改变。LLM 分解存在运行波动，因此 Deep 的 0.705 与 0.673 不应解释为代码退化或提升。

类别级 AFTER：

| 类别 | Normal Recall | Deep Recall |
|---|---:|---:|
| exact named | 0.500 | 0.500 |
| named alias | 0.600 | 0.600 |
| multi evidence | 0.733 | 0.867 |
| temporal/version | 0.833 | 0.933 |
| semantic | 0.800 | 0.500 |

Deep 对多证据和时间版本有帮助，但语义类明显回落，命名类没有改善，所以不满足“通用 Named Evidence Anchor”的实施条件。

### 3.4 为什么没有实现 Named Evidence Anchor

基准显示：明确标题且已入库的 R01/R02/R03 可正常命中；四篇论文是 missing document；唯一已入库别名失败 `GAM → 全局变量实现2`，单独检索 `GAM` 也不能让目标进入最终 Top‑K。失败主要在 rerank 候选缩减，不是 Researcher 忘记保留命名实体。

如果此时增加 anchor，只会针对已看过案例做局部优化，同时增加查询成本，无法证明泛化。本轮按停止条件 A 保留现有 Retrieval Pipeline。

## 4. Reviewer premise 边界

### 4.1 四态协议

`ReviewReport.premise_assessment` 固定为：

```text
supported
unsupported
insufficient
not_applicable
```

`_is_premise_task()` 只判断用户是否明确要求核验可判真假的前提，不判断真假。通用触发形式包括“验证”“核验”“是否成立”“是否可以认为”，以及“判断所有成员是否必须……”等明确命题。

以下任务不是 premise：

- 比较 A 和 B；
- 总结三份资料；
- 给出研究建议；
- 判断两份资料是冲突还是互补。

当不是 premise task 时，即使 Reviewer 模型错误返回 unsupported，也会被确定性归一：

```text
premise_assessment = not_applicable
premise_source_ids = []
false_premise_detected = false
删除 false_premise review item
```

Generation 在 `not_applicable` 下不写“前提核验”上下文，也不在答案顶部注入前提结论。

### 4.2 已解决和仍未解决的边界

“普通问题被错误加前提提示”已经通过通用测试解决。另一方面，明确 premise task 内部的 supported / unsupported / insufficient 判断仍依赖 Reviewer 对证据的理解。Blind V2 自动 premise 指标显示这一能力仍不可靠，不能把“边界修好”表述成“前提判断准确”。

## 5. ACL 完整角色矩阵

独立测试在 `tests/test_deep_research_acl_matrix.py`。完整结果见 `data/深度研究V2权限矩阵验证报告.md`。

覆盖用户：anonymous、ordinary_user、project_member、project_lead/authorized user、non_member。覆盖 visibility：public、project、restricted。覆盖 project relation：same、other、none。

除直接矩阵外，测试故意让被拒绝 restricted 文档混入检索 pipeline 返回，并逐层扫描：

```text
EvidencePackage
AnalysisReport / Claim
ReviewReport
retrieval_context
research_trace
source cards
Final Answer
```

初检索和 Revision 补检索都执行二次 `check_doc_access`。测试中的拒绝标记没有出现在任何阶段，ACL violation = 0。

本轮没有修改权限模型。尤其没有将“project visibility 但无 project restriction”的历史语义重新定义。

## 6. Trace 与失败归因

Trace 仍存于 AgentState 和评测 JSON，不引入外部平台。

Researcher 现在记录 evidence count、missing subquestions、每条 query 的 decision、rewrite history 和 returned titles。Analyst 记录证据到 Claim 的覆盖以及未进入 Claim 的 evidence IDs。Reviewer 记录被拒 Claim、issue type 和具体理由。Revision 记录 targeted queries、补充证据、Claim 增删和最终验证结果。Generation 记录 omitted validated claim IDs 及 final validated-claim coverage proxy。

顶层统一归因只能是：

```text
retrieval | analysis | review | generation | knowledge_gap | acl | none
```

阶段耗时聚合在 `research_trace.stage_latency_ms`。评测数据有 gold 时，还会用 retrieval-only runner 进一步区分 missing document、rerank failure 等细类。

“Final validated-claim coverage”是确定性词汇覆盖 proxy，不是假装成语义事实准确率。

## 7. Development Eval V2

41 条原数据仍是 Development Eval。A/B 使用冻结历史结果，C 在 V2 实现上重跑。它用于调试和冻结，不能宣称 blind generalization。

| 方案 | 关键点 | 引用覆盖 | 引用支持 proxy | 文档召回 | premise | P50/P95 | calls |
|---|---:|---:|---:|---:|---:|---:|---:|
| A | 0.915 | 0.518 | 0.966 | 0.598 | 0.889 | 6.0s/7.4s | 1.98 |
| B Normal | 0.939 | 0.516 | 0.970 | 0.632 | 0.889 | 7.0s/8.9s | 1.98 |

这里的 premise 评分已修正为只读取答案中的明确前提结论，不再被正文局部“证据不足”反向覆盖。Deep 在 premise 上仍落后，属于真实限制。

### 9.4 Label-blind packet

盲评包逐题固定随机化为候选甲/乙，不展示方案名、used_agent、trace、latency 或调用次数。只用确定性规则去掉固定 Research Brief 一级标题；没有 LLM 改写，没有改变事实、引用、句子顺序或结论。

由于原始写作风格仍可能泄露方案，它只能称为 `label-blind but potentially style-identifiable`，不能称 double blind。

Codex 没有打开 `深度研究V2盲评密封映射.json`，也不会为 V2 填写最终人工评分。当前状态是：

```text
Implementation + automatic eval complete,
independent human review pending.
```

## 10. 前端显式入口

对话输入框上方新增最小二选一：

```text
回答模式：普通 | 深度研究
                   多阶段证据分析，耗时更长
```

默认普通，不自动推荐 Deep。选择只作用于当前请求；提交后立即恢复普通。刷新和新会话也默认普通。SSE 请求体透传 `research_mode`，其他 Normal UI 行为不变。

Playwright 真实点击验证捕获到两个请求依次为 `normal`、`deep`，并验证 Deep 提交后、刷新后、新会话均恢复 Normal；无 browser console/page error。

## 12. 当前能与不能声称什么

能声称：Deep 是显式、有界、ACL 安全且可观测的三角色研究流程；它在冻结 V2 自动评测中提高证据召回与引用覆盖，但约慢四倍、调用约 3.9 倍。

不能声称：Deep 全局优于 Normal；temporal_conflict 的 V1 人工优势已经在更大样本中重复；named multi-evidence 已有用户可感知稳定收益；recommendation/Research Brief 不再退化；premise 判断可靠；Blind V2 已完成人工评审。

下一步不是继续调 Agent，而是由独立评分者完成盲评。如果人工结果不支持 V1 边界，应降低产品声明；如果不支持任何稳定净收益，可以关闭 `DEEP_RESEARCH_ENABLED`，保留为可复现实验。
